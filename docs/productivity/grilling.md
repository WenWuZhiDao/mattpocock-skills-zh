## 它做什么

`grilling` 是那个在任何人动手之前，对一个计划、一个决定或一个想法进行压力测试的访谈循环。它把主题建模为一棵**决策树**——每一个决定都分叉出挂在它下面的那些决定——并逐个分支地访谈你，直到没有任何东西被默默假定。

它不是一次问一个问题，也不是一次把所有问题都问完。每一**轮**都会问整个**前沿**：每一个前置条件都已敲定的决定，仅此而已。如果两个问题中一个依赖于另一个，它们绝不会共处一轮——一个悬于尚未解决的答案之上的问题，属于更晚的一轮。你的回答敲定了一些决定，前沿随之向外推移，下一轮便问那些被解锁的问题。十三个问题通常落在大约三轮里，而不是十三轮。

## 何时使用它

输入 `/grilling`，或者当某个任务合适时[智能体（agent）](https://www.aihero.dev/ai-coding-dictionary/agent)会自行使用它。它是拷问家族里唯一由模型调用的[技能（skill）](https://www.aihero.dev/ai-coding-dictionary/skill)，这也是你很少亲手输入它的原因：通常是某个你*确实*输入了的技能在替你运行它。

直接输入 `/grilling` 得到的是纯粹的访谈，别无其他。当你想要的不止于此时：

| 你手上有什么 | 使用 |
| --- | --- |
| 你并不在某个工作目录中工作 | [grill-me](https://aihero.dev/skills-grill-me) —— 同样的[会话（session）](https://www.aihero.dev/ai-coding-dictionary/session)，只是换了个智能体永远不会自行触发的名字 |
| 你在一个工作目录中 | [grill-with-docs](https://aihero.dev/skills-grill-with-docs) —— 同样的会话，并且它会一路写入 `CONTEXT.md` 和 ADR |
| 一项大到一个会话容纳不下的工作 | [wayfinder](https://aihero.dev/skills-wayfinder) —— 它绘制一张地图，并在决策工单内部运行拷问 |
| 一个交谈无法解决的问题——某样东西应该看起来或感觉如何 | [prototype](https://aihero.dev/skills-prototype) —— 搭出一次性版本，然后回来 |
| 你自己的、需要一场访谈的技能 | 从它里面调用 `/grilling`，而不是再写一个访谈 |

## 轮次、前沿，以及谁来决定

三个概念承载了整个技能。

**决策树**是对主题的建模：一些决定，下面挂着一些决定。**前沿**是那组前置条件全部敲定的决定——目前唯一能诚实地问出口的问题。一**轮**就是一个前沿，被完整地问出、完整地答完。

在一轮之内，每个问题都以固定的形态出现：编号并带标题，置于 `❓` 之后，然后是正文，接着是智能体推荐的答案，单独占据一行 `➡️`。这正是让一轮可以按编号作答的原因——「1 是，2 选第二个选项，3 否，理由如下」——而不必把问题逐字引述回去。这种格式有一个已知的粗糙之处：推荐意见有时会*反对*问题字面上的措辞，所以同意推荐意见意味着对该问题回答「否」。遇到这种情况时，回应推荐意见，并说明清楚。

设计的另一半，是事实与决定之间的划分。事实是技能自己的活儿：当一个前沿问题需要某样[环境（environment）](https://www.aihero.dev/ai-coding-dictionary/environment)能解决的东西时，它会派出一个[子智能体（sub-agent）](https://www.aihero.dev/ai-coding-dictionary/subagent)去查明，而不是问你。它不会因此阻塞——只有位于某次进行中探索下游的问题才会等待。决定归你，它必须等你。一个运行 `grilling` 的智能体若自己回答了自己的决定，那是它破坏了这个技能，而不是宽松地诠释了它。当前沿为空时会话结束，而且在你确认已达成共识之前，它不会对你所同意的内容采取行动。

诚实的局限：前沿是智能体的判断，而非计算出的图。它可能把两个问题放进同一轮，事后才发现其中一个答案本应改变另一个。除了告诉它之外，没有任何防护措施——告诉它会在下一轮重新打开受影响的分支。

## 常见问题

**我能改回一次问一个问题吗？**
可以，而且很大一部分受众就这么做。把这一行加入你的全局 `CLAUDE.md`：

```
When grilling, ask one question at a time.
```

以轮次为默认的做法确实存在争议。阅读速度慢的、用第二语言工作的、或把顺序格式当作专注支架的实践者，都反映一次一个的节奏对他们更好，而这个退出选项是被支持的，而非勉强容忍的。

**`/batch-grill-me` 去哪了？**
进了这个技能。基于轮次的提问曾短暂地作为一个独立技能发布，随后并入了 `grilling` 本身，于是所有建立在该原语之上的技能——`grill-me`、`grill-with-docs`、`triage`、`wayfinder`——一次性都得到了它。没有 `batch-grill-me` 可安装，也没有单独的顺序技能；上面那行 `CLAUDE.md` 就是回到一次一个的办法。

**一次问一整轮，肯定会漏掉我先前的回答本会引出的问题。难道不是吗？**
这是对轮次设计最常见的反对意见，而前沿正是对它的回答：一轮里只会包含彼此不相依赖的问题，所以一轮里的任何答案都不会使该轮里的另一个问题失效。答案仍然会重塑下游的一切——下一轮是重新计算的，而非预先写好的。你损失的，比「一次问所有问题」所暗示的要小，又比「毫无损失」要大：见上文关于前沿的局限。

**它问完了问题就开始动手构建。**
存在一道确认关卡正是为此：技能并非在前沿清空时结束，而是在你说共识已达成时结束。更弱、更快的[模型（models）](https://www.aihero.dev/ai-coding-dictionary/model)仍会破坏它——这在低推理强度或非前沿模型上被报告得最多，它们把「访谈直到达成共识」坍缩成几个问题加一份大纲。如果你的模型这样做，可靠的修法是在你自己的 `AGENTS.md` 或 `CLAUDE.md` 里加一行，告诉智能体未经许可不得实现。

**它自己回答了自己的问题，而不是问我。**
那是这一次运行中的一个 bug，而非预期行为，也正是技能正文里把事实与决定分开的原因。它最常出现在另一个技能在「解决这张工单」的框架里运行 `grilling` 的场合，那里周围的任务读起来像是「继续推进」的许可。同样的约束也解释了为何没有异步模式：有人要求过一个能读取 GitHub issue 并发布一份合并决策备忘的变体，那是另一个技能，因为一场无人回答的拷问会话产出的是智能体的意见，而非你的。

**我能给问题数量设上限吗？**
不能，而且上限是被刻意排除在范围之外的。有些计划需要三个问题，有些需要五十个；一个固定的天花板要么把难的情形截断，要么在容易的情形上显得武断。用平实的语言掌舵才是预期的控制方式——让它收尾，或者停下并接受计划当前的样子。如果一场会话运行得非常久，原因通常是范围太大了；把工作拆开，逐块拷问。

**我单独装了 `grill-me`，可什么都没发生。**
`grill-me` 是一个只有一行的技能，其整个正文就是「运行一次 `/grilling` 会话」，所以它也需要装上这个技能。`grill-with-docs` 同理，而且它还额外需要 [domain-modeling](https://aihero.dev/skills-domain-modeling)。安装整套可以避免这个问题；选择性安装意味着连同基础原语一起装。

**`grill-with-docs` 运行了，但它从没加载 `grilling`。**
这是一个真实且未修复的粗糙之处，在各种[框架（harness）](https://www.aihero.dev/ai-coding-dictionary/harness)和模型上都有报告：一个技能提到另一个技能，并不能可靠地使那个技能被加载，而 `grill-with-docs` 提到了两个。判别的标志是：一场会话一次性把所有问题都问出来，且不附带任何推荐意见——那是模型在即兴发挥一场访谈，而非运行本技能。直接问智能体它是否加载了 `grilling` 和 `domain-modeling`，通常能挽回。

## 它生效的标志

- 一轮以带编号的列表到来，每个问题的推荐意见在单独的 `➡️` 行上，而你能按编号回答一整轮。
- 一轮里没有任何东西需要同一轮里的另一个问题先被回答。
- 后面的轮次会问一些第一轮问不出来的东西。
- 它会主动去查明事实——读取文件、派出子智能体——而不是问你一个它本可以自己查明的东西。
- 后台运行的调研不会让这一轮卡住；只有依赖它的问题才等待。
- 它在最后停下来，请你确认共识已达成，而不是直接开工。
- 问题数保持高企，而轮次数保持低位。

## 它的位置

`grilling` 是一个**原语**，而非你排入日程的某个步骤：它是访谈技艺的唯一真理来源，集中保存在一处，好让每个需要访谈的技能都去调用它，而不是自己发明一个。[grill-me](https://aihero.dev/skills-grill-me) 和 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 是它两扇由用户调用的正门，而 `grill-with-docs` 是主构建链开始的地方，位于 [to-spec](https://aihero.dev/skills-to-spec) 之前。[wayfinder](https://aihero.dev/skills-wayfinder) 运行它来解决决策工单，[triage](https://aihero.dev/skills-triage) 运行它把一份含糊的报告拷问成一份可执行的报告，而 [improve-codebase-architecture](https://aihero.dev/skills-improve-codebase-architecture) 运行它，在你选定了一个要深挖的候选之后走一遍这棵树。当你不确定哪个入口合适时，[ask-matt](https://aihero.dev/skills-ask-matt) 会为你导航。
