## 它做什么

`teach` 把你运行它所在的目录变成一个常驻的教学工作区，并跨越许多个[会话（session）](https://www.aihero.dev/ai-coding-dictionary/session)、以简短自足的 HTML 课程教你一个主题。

它不从[模型（model）](https://www.aihero.dev/ai-coding-dictionary/model)已经知道的东西里教起。[参数化知识（parametric knowledge）](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge)被当作不可信：在教之前，它会去寻找高可信度的资源，把它们记录在 `RESOURCES.md` 里，并在每一课里引用它们。另一个结构性事实是它是[有状态的（stateful）](https://www.aihero.dev/ai-coding-dictionary/stateful)——使命、资源、课程，以及你学过什么的记录，全都以文件形式住在这个目录里，因此下一个会话是从这些文件接续，而不是从上一场对话剩下的东西接续。

## 何时使用它

你通过输入 `/teach` 来调用它——[智能体（agent）](https://www.aihero.dev/ai-coding-dictionary/agent)不会自行使用它。

当学习本身就是这个项目时使用它：一门语言、一个框架、一个你刚加入的代码库、瑜伽、着色器、某项认证。它不是用来临场解释一件事的工具。

| 你想要什么 | 该用什么 |
| --- | --- |
| 用数周时间学一个主题，会话逐步累积 | `teach` |
| 在你已经身处的会话里解释一个想法 | 就在那个会话里直接问 |
| 智能体上一条消息因为没听懂而重新表述一遍 | [wait-what](https://aihero.dev/skills-wait-what) |
| 磨砺你已有的思考，而非获取新材料 | [grill-me](https://aihero.dev/skills-grill-me) |
| 一个后台智能体去读[一手来源（primary sources）](https://www.aihero.dev/ai-coding-dictionary/primary-source)并给你留下一份带引用的文档 | [research](https://aihero.dev/skills-research) |
| 学习拷问途中冒出来的东西，又不打断[拷问（grilling）](https://www.aihero.dev/ai-coding-dictionary/grilling) | [handoff](https://aihero.dev/skills-handoff) 出去到一个教学工作区，然后在那里 `teach` |

## 前置条件

`teach` 构建的是一个目录，而非产出一个文件，而且这个技能假定每个工作区只有一个使命——所以请在一个你乐意整个让给单一主题的地方运行它。把它放在你正在做的项目之外：推荐的归宿是一个独立的仓库，而不是一个全局的 `~/.learnings/` 文件夹或正在做的项目本身。一个专用仓库还让这些课程可提交，团队正是这样分享它们的。

在那个目录里累积的东西：

| 路径 | 它装什么 |
| --- | --- |
| `MISSION.md` | 你为何要学这个。其他一切都挂在它上面；如果它缺失，`teach` 做的第一件事就是访谈你，直到它不再缺失 |
| `RESOURCES.md` | 它据以教学、经过甄别的来源，分为知识（Knowledge）与智慧（Wisdom，即社群）两部分 |
| `lessons/*.html` | 带编号的课程——教学的基本单元 |
| `reference/*.html` | 压缩过的速查表、算法、术语表：你真正会反复回看的文档 |
| `learning-records/*.md` | ADR 风格的笔记，记录你已被证实学会的东西，用于决定接下来教什么 |
| `assets/*` | 可复用组件——首先是一张共享样式表——好让课程看起来像同一门课 |
| `NOTES.md` | 你陈述的教学偏好 |

关于这份清单，有两条诚实的注记。术语表适合大多数主题，但这个技能附带了一份 `SKILL.md` 不再链接的 `GLOSSARY-FORMAT.md`，所以你只有开口要才会得到一个（[issue #559](https://github.com/mattpocock/skills/issues/559)）。而且工作区并不总是创建在你预期的地方——在你在其之上构建一门长课程之前，先看下面第一个问题。

## 是存储强度，而非流畅感

要用来思考的词是**存储强度（storage strength）**：长期留存，与**流畅感（fluency）**相对——后者是当下那种、在你阅读时感觉像是精通、一周后却已消失的即时回忆。`teach` 通过合意难度（desirable difficulty）——提取练习、间隔、交错——来建立前者。知识先行，在这里难度是敌人，因为它会吃掉你理解所需的工作记忆；随后技能通过一个紧密的反馈循环来打磨，在这里难度是工具。

有两样东西引导你会被教什么。**使命**——你想要这个的具体现实理由——为每一课奠定根基；没有它，课程会飘向抽象，也没有东西来决定接下来教什么。`teach` 从使命和学习记录中，在你的**最近发展区（zone of proximal development）**内挑选下一课：足够有挑战、要费些力气，又不至于远到不再可学。

这也是它会反驳而非顺从的原因。一个需要**智慧**——现实世界判断力——的问题，会得到一次尝试性的回答，然后附上一个指向某个社群的指引，你可以去那里检验它。测验是一道关卡，而非一道手续：一位用户报告说他说了「多谢」，却被告知这次演练还没结束。

## 课程、参考文档与组件

一**课**是一个自足的 HTML 文件，短到能在一次坐下之内学完，与使命相系，给出一个实实在在的收获。它引用自己的来源，推荐一份一手来源让你亲自去读，并链接到姊妹课程和参考文档。

值得知道的划分：课程很少被重看，参考文档则会。所以一课的压缩精华——语法表、算法、体位序列、术语表——属于 `reference/`，而不该埋在引入它的那一课里。

课程是从 `assets/` 里的**组件**搭建起来的：样式表、测验小部件、模拟器、图示辅助工具。复用是默认。智能体在撰写一课之前先读 `assets/`，从已有的东西搭起，而任何第二课可能用到的新东西都写成组件而非内联。共享样式表是每个工作区赢得的第一个组件；正是它让输出不至于沦为一堆一次性的东西。

## 常见问题

**它把文件放哪了？我的最后跑到了 `~/.claude/skills` 里。**
一个真实且未关闭的 bug（[#377](https://github.com/mattpocock/skills/issues/377)）。`SKILL.md` 同时用 `./` 指代两个不同的根：`./MISSION-FORMAT.md` 及其同类确实位于已安装技能里 `SKILL.md` 旁边，而 `./lessons/`、`./reference/`、`./learning-records/` 和 `./assets/` 本应在你的目录里。一个把第一类相对于技能安装目录解析的智能体，会接着把第二类也解析到那里，把你的课程写进技能文件夹。在你在其之上构建之前，先检查第一课落在了哪里，并在开始时明确点名目录，而不要依赖「当前目录」会被理解。

**我该待在一个会话里，还是每一课开一个新会话？**
三种做法都行——待在同一个会话里、在新会话里重新调用 `/teach`，或在同一个文件夹里打开一个新会话。每一课都是它自己的一次调用。连续性来自文件夹，而非对话。常见做法是在工作区里打开一个全新会话，说 `/teach next lesson for <topic>`。

**我怎么知道它没在教我一些它编出来的东西？**
仅凭这个技能的一面之词，你无法知道。你要去读一手来源。`teach` 不可靠到能被不加核查地信任，任何建立在 LLM 上的技能都不能。那套奠基机制——`RESOURCES.md`、每一课里的引用、每一课一份推荐的一手来源——的存在是为了让核查变得廉价，而不是为了消除核查的必要。这种失败并非假想：一位学习二阶魔方的用户被给了一套解不开它的、捏造的转动序列。对这类情形的诊断清单是模型、框架、推理强度——以及来源是什么。在带有精确记号法的程序性领域风险最高，而在输出能被立即验证之处最低，比如你能运行的代码。

**测验的正确答案总是第一个选项。**
被数人确认，在 Sonnet、Opus 和 GLM 上皆是，且仍未修复。`SKILL.md` 现在要求每个答案字数相同，这消除了另一个破绽——正确答案曾经是唯一被完整论证的那个——但对位置只字未提。一位贡献者测试了一个指令层面的位置修法，报告说正确答案在九节课里 33 次中有 33 次仍落在 A 位（[#335](https://github.com/mattpocock/skills/issues/335)），这指向 `assets/` 里一个会打乱顺序的测验组件才是真正的修法，而非更好的措辞。在那个组件发布之前，把答案位置当作无意义。你的 `assets/` 目录归你改，所以要一个在渲染时打乱顺序的组件，是一个正当的本地修法。

**它假定我已经知道某些东西，还用了它从不定义的术语。**
最常见的实质性抱怨。没有评估步骤：`teach` 从使命和学习记录推断你的水平，而在第一节课里没有学习记录。一位在 wayfinder 流水线里运行它的用户说得直白——「它从没做拷问来确立我的起点，所以对我已经知道什么做了大量假设。」另一位报告课程倚赖未定义的行话，还有一课为他们的硬件量身定制，讲了硬件能做什么，却从不说它不能做什么。有两件事有帮助：在第一条消息里陈述你的先备知识和你的欠缺，并在一课没讲到位时大声纠正水平，因为纠正会变成一条学习记录，引导下一课。一个明确的知识评估步骤是一项长期的功能请求（[#725](https://github.com/mattpocock/skills/issues/725)），而非已发布的行为。

**它做间隔重复吗，它知道何时该停止教学吗？**
第一个问题答否，第二个不可靠。间隔与交错是课程所据以设计的原则，但没有东西来安排一次复习，也没有 Anki 或日历集成——两者都是反复出现的请求。相关的欠缺是退出标准：正如一位用户所说，`teach`「擅长做出下一课，但不太擅长知道何时该停下来、转向复习或真正的练习」。如果你想要复习或演练而非新材料，就开口要；这个技能不会自行提出切换。

**它只对代码有用吗？**
不，而且非编码用途是记录中更大的一部分：韩语、日语的敬语体、钢琴、吉他、桌游设计、OpenSCAD、电影剧情、Azure 和 CCNA 认证、大学考试，还有八岁和十岁的孩子拿到关于密室逃脱和火蝾螈的可打印读物。技能里没有任何东西是编程专属的——使命、资源、最近发展区和演练，在任何领域都以同样方式运作。在代码之内，被报告的最强用途不是从零学一门语言，而是在一个陌生代码库或一个新团队的技术栈里找到方向。

**我该用哪个模型运行它？**
没有权威答案，而且被报告的差异很大。更高的[推理强度（reasoning effort）](https://www.aihero.dev/ai-coding-dictionary/effort)被报告能产出明显优于中等设置的课程。一位用户把同一个技能通过 Copilot CLI 配 Codex 运行，得到的是一张 30 行的 HTML 卡片，而 Claude Code 产出的是一整课。它在 Claude Cowork 里可不加修改地运行，取决于你的组织是否允许在那里添加技能。如果课程出来单薄，先换模型、[框架（harness）](https://www.aihero.dev/ai-coding-dictionary/harness)或推理强度，再去改你的提示词。

## 它生效的标志

- 在一个空目录里它做的第一件事，是访谈你为什么想要这个，而不是产出一课。
- `RESOURCES.md` 在课程之前先填满，而每一课都点名一份值得你亲自去读的一手来源。
- 一课里的论断都带着向外的链接。一课没有引用，就是技能在凭记忆教学。
- 一课占用一次坐下的时间，并让你能做一件你此前不会做的事。
- 在文件夹里打开一个全新会话并说「下一课」，会续上这门课，而不是重新开始。
- `learning-records/` 在增长，而课程不再重教你已经证实掌握的东西。
- 课程看起来像同一门课——它们链接 `assets/` 里的样式表，而不是各自带一份。
- 一个需要判断力的问题，会把你指向一个论坛、subreddit 或课堂，而不只是给一个答案。

## 它的位置

`teach` 是一个**随时可取用的独立技能**。它不是构建链里的一个步骤，也不与工程流程共享任何产物；它拥有自己的目录，并在那里存续、只要主题还在。

它唯一真正的邻居是 [handoff](https://aihero.dev/skills-handoff)，通过 Matt 命名为「如果我正因为一件我不理解的事而被拷问该怎么办？」之答案的那种组合：别停下拷问去学——`/handoff` 到一个教学工作区，在那里用 `/teach` 学会它，然后回去、从你离开的地方接着来。附近的替代选项是 [research](https://aihero.dev/skills-research)，当你想要的是一份带引用的文档、而非课程与留存时。当你不确定哪个技能或流程合适时，[ask-matt](https://aihero.dev/skills-ask-matt) 会在整套技能上为你导航。
