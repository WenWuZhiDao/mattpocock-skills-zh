## 它做什么

`handoff` 把你所在的这场对话压缩成一份**交接文档**——一个 markdown 文件，写入你操作系统的临时目录而非工作区，一个全新的[智能体（agent）](https://www.aihero.dev/ai-coding-dictionary/agent)可以读取它来接手工作。

它买到的是**可移植性**，而不是压缩。这让这个技能比听起来要窄。只有当工作必须*旅行*时——去往一个新的[框架（harness）](https://www.aihero.dev/ai-coding-dictionary/harness)、一个新的目录、一位同事，或一个你想分叉出去的支线任务——你才需要一个文件。如果没有东西要旅行，你就不需要交接：留在[会话（session）](https://www.aihero.dev/ai-coding-dictionary/session)里、`/clear`、一个[子智能体（subagent）](https://www.aihero.dev/ai-coding-dictionary/subagent)以及 `/compact` 覆盖了寻常的阶段收尾情形，而 `/compact` 覆盖它的频率比这个技能高。

## 何时使用它

你通过输入 `/handoff` 来调用它——智能体不会自行使用它。附上一条关于下一个会话是做什么用的说明，文档便会为它写好。

四种情形构成了全部触发条件：

| 情形 | 为何需要文件 |
| --- | --- |
| 切换框架——Claude → Codex | 新框架看不到旧的[上下文（context）](https://www.aihero.dev/ai-coding-dictionary/context) |
| 移动到另一个目录或仓库 | 原型目录是常见情形 |
| 把工作发给一位同事 | 他们需要一份能读的东西 |
| 分叉一个阶段中途发现的支线任务 | 你继续干活；第二个智能体接手这个分叉 |

除此之外的任何情况——同一个框架、同一个目录、你已经[拷问（grilling）](https://www.aihero.dev/ai-coding-dictionary/grilling)完毕正转向实现——`/compact` 才是该走的路。[ask-matt](https://aihero.dev/skills-ask-matt) 在阶段边界上把这五个选项按顺序的决策树串起来。

## 分叉是人们跳过的用法

这个技能的描述读起来像是会话恢复：写一份摘要，在这里结束，在那里继续。这样读，它看起来就像一个更差的 `/compact`，于是被草草略过。分叉这一情形才是值得了解的。你**留在自己的会话里**，把累积的上下文的一份副本交给一个并行工作的第二个智能体。

那正是绕道 [prototype](https://aihero.dev/skills-prototype) 时所用的方式。你正深陷一场设计对话，碰到一个只有运行代码才能解决的问题，而你不想把已经建立起来的这个线程花在查明它上面。交接给一个原型会话，拿到答案，把答案交接回来，再从原来的线程里引用它。两次跨越，一场活着的对话，什么都不必重新解释。

阶段边界上的五个选项里，有三个保留的是不同的东西：`/compact` 保留你的意图，`/clear` 什么都不保留，`/handoff` 保留工作移动的能力。

## 什么会旅行，什么不会

文档携带这个活着的线程——正在进行什么、为什么、接下来是什么——外加一个**建议技能（suggested skills）**小节，指明下一个智能体应当使用什么。写入之前，秘密信息会被脱敏。

它刻意不携带的，是任何已经被写下来的东西。规格、计划、ADR、issue、提交和 diff 都以路径或 URL 引用，绝不复制。这让文件保持小巧，也让已敲定的细节留在一处，而不是分散在会相互漂移的两处。

## 常见问题

**交接还是压缩？**
除非有东西在旅行，否则用 `/compact`。停留在同一个任务上是一次压缩，而非一次交接——同一个框架、同一个目录、你需要留在循环里，这正是阶段边界决策树在大多数日子里落脚的地方。`/handoff` 的优势不在于它总结得更好；而在于结果是一个你能带去 `/compact` 够不着的地方的文件。

**那么 compact、clear 和 handoff 之间真正的区别是什么？**
是三样不同的东西被保留下来。`/compact` 压缩当前上下文，让你在一个全新的窗口里继续——意图得以存续。`/clear` 清空窗口、从零开始——当你身后的一切都可丢弃时它是对的，而如果并非如此则它是单向的。`/handoff` 写出一个可移植的文件——工作在移动到别处后得以存续。请注意，这三者都把一个**[一手来源（primary source）](https://www.aihero.dev/ai-coding-dictionary/primary-source)**（如实发生的对话）变成了一个**[二手来源（secondary source）](https://www.aihero.dev/ai-coding-dictionary/secondary-source)**（对它的摘要）。继续下去是唯一不这样做的动作，这也是为什么它是第一个要被排除的选项。

**我的交接文件去哪了？**
临时目录，这是这个技能被报告得最多的摩擦点：路径很长，每个操作系统都不同，而在 Windows 上智能体有时要试好几次才能找到正确的那个。要回路径并在继续之前把它记好。用临时目录是刻意的：交接是一份过境文档，而不是一件你要维护的产物。它也不是持久的——见下一个问题。

**我的交接文件在两个会话之间消失了。**
有些环境会在会话之间清空临时目录——Codex 是被报告的情形——而 `/private/tmp` 会在重启时清空。如果下一个会话不会在一小时内开始，或者会在另一个框架下开始，请在文件一写好就自己把它复制到某个持久的地方。同样的道理适用于文档所*指向*的任何东西：一份引用了临时目录里其他文件的派发单，是下一个智能体无法跟进的派发单。

**我到底怎么把它交给下一个智能体？**
打开全新的会话，把它指向那个路径：读取这个文件，然后继续。指向文件，而不要把摘要粘贴进 shell 命令——一段含有反引号或 `$(...)` 的摘要在被插值进 `claude "<summary>"` 时会被搅乱，而常见的失败是无声截断而非报错，于是新智能体拿着一份悄悄残缺的简报开工。

**这和 `/branch`、`--fork-session`，或内置的 `/handoff` 是一回事吗？**
类似，但不完全相同，而且 `/branch` 在这里并不是一个已发布的技能——`/handoff` 才是规范名称。一个 fork 继承上下文的一份精确副本；这个技能产出的是一份*有的放矢*、瞄准某个既定的下一任务、装在文件里的压缩。凡是 fork 够用的地方——同一台机器、同一个框架、同一个目录——fork 更省事。一旦目的地是 fork 到不了的地方，文件就胜出。

**什么东西应该放进 `CLAUDE.md` 里？**
问问它下个月是否还成立。`CLAUDE.md` 是关于项目的常驻上下文，无论是否相关都会加载进每个会话。交接讲的是一件正在进行的工作，一旦那项工作落地它就死了。那些不断被反复解释的事实是 `CLAUDE.md` 的问题；一个半成品任务是交接的问题。

**它抓住了「是什么」，却没抓住「为什么」。**
一个公允且被反复提出的批评。有两件事有帮助。传入论据——告诉它下一个会话是做什么用的——好让与*那件事*相关的推理被保留下来，而不是被抹平。并留意会话从未真正核实过的自信断言：「X 还没建」「Y 已经做完」。下一个智能体把文档当作合同，不会去重新核对，于是一个被写成事实的信念，就成了随后一切的一个错误前提。在你把它交出去之前先读一遍文档，并把任何你只是假定的东西降级。

**它为什么是一个技能而不是一个斜杠命令？**
两者都行；它们适合不同的情形。作为一个技能，它通过与这里其他一切相同的安装路径来发布和更新，这正是让它可分享的原因——智能体不会自行触发它，这个约束由它的 frontmatter 设定，而非由机制设定。

## 它生效的标志

- 文档只是对话的一小部分，而规格、issue 和 diff 在其中以路径和 URL 出现，而非以复制的文本出现。
- 你能在不打开原会话的情况下冷读它，并知道接下来该做什么。
- 全新的智能体开始干活，而不是要你重新解释一遍设置。
- 在分叉情形下，你回来时原来的会话仍原封不动地待在那里。
- 建议技能小节指明的，正是你自己本会使用的那个技能。
- 里面没有任何密钥、令牌或密码。

## 它的位置

`handoff` 是一个**随时可取用的独立技能**，它生活在会话与会话之间的接缝处，而非某条构建链的内部——但它是一个很窄的技能，而诚实的地图是：你使用它的频率会低于阶段边界上另外四个选项。它最近的邻居是 [prototype](https://aihero.dev/skills-prototype)，因为原型生活在自己的目录里，而进出往返恰恰是这个技能所服务的那次跨越。当你处在一个边界上，拿不准该继续、清空、交接、委派还是压缩时，[ask-matt](https://aihero.dev/skills-ask-matt) 会串起为这五者排序的决策树——并在其余整套技能上为你导航。
