## 它做什么

`triage` 让你项目追踪器上的 issue 通过一个小小的分诊角色**状态机（state machine）**流转——给它们归类、验证声称、必要时拷问成形，并留下一份 ready-for-agent 的简报。

它从不盲目打标签。每个被分诊的条目恰好带一个**类别（category）**角色（`bug` / `enhancement`）和一个**状态（state）**角色（`needs-triage`、`needs-info`、`ready-for-agent`、`ready-for-human`、`wontfix`），并且它_推荐并等待_——它带着推理告诉你它对类别和状态的判断，然后只按你的指示行动。在任何东西被提升到 `ready-for-agent` 之前，它先验证声称：一个 bug 会被复现，一个 PR 会被 checkout 并运行。

## 何时使用它

你通过输入 `/triage` 并用自然语言描述你想要什么来调用它——智能体不会自行触及它。"Show me anything that needs my attention"、"let's look at #42"、"move #42 to ready-for-agent"。

当你的 issue 追踪器有原始、未评估的报告，你想把它们分类、验证并变成智能体或人能拿起来做的工作时，触及它。要把一次已敲定的对话变成一份新规格，改用 [to-prd](https://aihero.dev/skills-to-prd)；要把一份既有的 PRD 拆成工单，用 [to-issues](https://aihero.dev/skills-to-issues)。`triage` 是相反方向——它处理_已经_落进追踪器的东西。

## 前置条件

`triage` 读写你的 issue 追踪器，所以 [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills) 必须先配置好追踪器和标签映射。上面的角色名是**规范的（canonical）**——你追踪器中实际的标签字符串可能不同，而那份映射正是 setup 所提供的。配置还决定外部 PR 是否算作一个请求来源，以及谁算作外部。

## A PR is an issue with attached code

在追踪器把外部 pull request 当作一个请求来源的地方，`triage` 让它们走过_同一_状态机：相同的类别角色、相同的状态、相同的转换——只是那些状态对照 diff 而非报告来读。`ready-for-agent` 意味着已附上简报、且智能体应该在代码上迈出下一步；`ready-for-human` 意味着它可以合并了。发现过程只呈现外部 PR，但一个被明确点名的 PR 无论作者是谁总会被分诊。

## Verify before you brief

把 `triage` 与临时打标签区分开的那一步是验证。它从报告者的步骤复现 bug，或 checkout PR 并运行测试，然后回报：带一条代码路径确认、失败，或细节不足（这本身就是一个强烈的 `needs-info` 信号）。它还跑两个代码库检查——**冗余**（这是否已经实现了？那它就是 `wontfix`）和**先前拒绝**（`.out-of-scope/` 是否已经说过不？）。一份经确认的验证造就强得多的智能体简报；猜测则不然。

## 它生效的标志

- 它触碰的每个条目都以恰好一个类别角色和一个状态角色结束——绝不为零，绝不有两个相冲突的状态。
- 它交给你一份带推理的推荐并等待，而不是自行重新打标签。
- 在任何东西到达 `ready-for-agent` 之前，bug 被复现、PR 被运行。
- 它发到追踪器的每条评论都以 `> *This was generated by AI during triage.*` 免责声明开头。

## 它的位置

`triage` 是对你 issue 追踪器的**周期性维护**一遍——每当报告堆积时运行它，以让队列保持有序、`ready-for-agent` 那一列值得信赖。它位于追踪器的最前端，在构建链的上游：它写的简报正是 [tdd](https://aihero.dev/skills-tdd) 后来拿起来实现的东西。当一个请求需要磨快时，它依靠 [grilling](https://aihero.dev/skills-grilling) 和 [domain-modeling](https://aihero.dev/skills-domain-modeling) 一次一个问题地把它拷问成形。它的近邻是 [to-prd](https://aihero.dev/skills-to-prd)，后者从一次新对话中填充追踪器，而 `triage` 处理那里已经有的东西。当你不确定哪个技能或流程契合时，[ask-matt](https://aihero.dev/skills-ask-matt) 会为你路由。
