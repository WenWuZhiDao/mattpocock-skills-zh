## 它做什么

`prototype` 构建一个小而可丢弃的程序，它唯一的职责就是回答一个设计问题——这个状态模型感觉对不对，或者这个 UI 该长什么样。

代码**从第一天起就是用完即弃的**，并被如此标注。它不带测试、不带超出能跑起来所需的错误处理、不带抽象、也不带持久化。要点是快速学到点东西然后删掉它——所以一旦你开始给它做加固，你就不再是在做原型了。

## 何时使用它

输入 `/prototype`，或者当任务契合时智能体会自动触发它。

当你有一个在纸上难以定论的设计问题时，就用它——一个你脑子里装不下所有情形的状态机，或者一个不亲眼看几个版本并排就想象不出来的界面。如果反过来，是某个已经构建好的东西出了毛病、你需要弄清原因，那就用 [diagnosing-bugs](https://aihero.dev/skills-diagnosing-bugs)；做原型探索的是要构建什么，而不是已构建之物为何坏了。

## 两条分支

问题决定形状，而形状有两种：

- **"这个逻辑／状态模型感觉对吗？"**——一个微型的交互式终端应用，把状态机推过那些别扭的情形，在每个动作之后打印完整状态，好让你看清什么发生了变化。
- **"这个该长什么样？"**——在同一条路由上做几个截然不同的 UI 变体，通过一个浮动条切换，好让你比较真实的渲染而不是凭空想象它们。

选错分支会浪费掉整个原型，所以问题排在最前。两条分支都把状态保存在内存里、用一条命令运行，并在每一步呈现完整状态。

## 把原型当作第一手来源保留

一个完成的原型留下两样东西。**答案**——那个定论加上它所解决的问题——是你要持久捕捉的东西（一条提交信息、一份 ADR、一个 issue）。**原型本身则是第一手来源**——答案由之而来的、可运行的证据。

原型不该待在主分支里：没有测试、没有错误处理、没有任何要维护的东西。但这不是销毁它的理由。一旦答案被捕捉，就把任何已验证的决策融进真实代码，然后把原型捕捉到一条用完即弃的分支上——移出主分支，永不合并——并在实现 issue 上留一个指向它的上下文指针。主分支保持干净；原始探索则离想重跑它的任何人只有一键之遥。一个烂在主分支里的原型已经活过了它的用途——一个作为第一手来源被捕捉到旁支上的原型则没有。

## 它的位置

`prototype` 是一个随时可取用的独立技能：你切入它去解决一个设计问题，然后再切出来。它的答案往往喂给下一步——一个已验证的状态模型或 UI 方向成为 [to-spec](https://aihero.dev/skills-to-spec) 落笔的稳定输入，或者一项值得通过 [domain-modeling](https://aihero.dev/skills-domain-modeling) 记录的架构决策。当你不确定该用哪个技能或流程时，[ask-matt](https://aihero.dev/skills-ask-matt) 会为你指路。
