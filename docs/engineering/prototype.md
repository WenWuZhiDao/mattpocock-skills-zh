## 它做什么

`prototype` 编写**回答一个问题的一次性代码**——这个状态模型感觉对不对，或者这个屏幕该长什么样。问题居于首位，并决定其后一切的形状；一个回答错误问题的原型是纯粹的浪费，无论它看起来多好。

一次性是对代码*如何书写*的约束，而非销毁它的承诺。没有测试、除了让它跑起来所需之外没有错误处理、没有抽象、没有持久化——因为这些都无助于你学到你正试图学的那一件事。存活下来的是答案，被折进真实代码，以及原型本身，停在 main 之外的一个分支上，作为答案由此得来的证据。

## 何时使用它

输入 `/prototype`，或者当某个任务契合时[代理](https://www.aihero.dev/ai-coding-dictionary/agent)会自动使用它。

一撞上你靠交谈无法定夺的问题就使用它——一个你脑子里装不下其边界情况的状态机、一个你不把三个版本并排看到就想象不出的屏幕。[盘问](https://www.aihero.dev/ai-coding-dictionary/grilling)会话恰恰在这类问题上膨胀：代理换个说法、你猜、范围随不确定性一同增长。停止盘问，构建一次性版本，看它，然后用一行作答。反之，如果已经构建好的某样东西行为异常、而你想知道原因，用 [diagnosing-bugs](https://aihero.dev/skills-diagnosing-bugs)——原型探索的是要构建什么，而非已构建之物为何坏了。

你也会不经选择就来到这里。[wayfinder](https://aihero.dev/skills-wayfinder) 会在它的地图上归档 `prototype` 决策[工单](https://www.aihero.dev/ai-coding-dictionary/ticket)，而处理其中一个就是这个技能。

## 两条分支

问题挑选分支，而两条分支产出截然不同的产物：

- **「这个逻辑/状态模型感觉对不对？」**——一个**可分享的单一 HTML 文件**。一个自包含的页面，无需构建也无需服务器，某人双击就能打开。它带有一个在每次点击后重新渲染的、加了标签的状态面板，用来以任意顺序戳弄模型的自由游玩按钮，以及分标签页的**引导式演练**——每个标签页一个场景，每个下面都有要按的有序按钮。一切都用领域语言加了标签，所以你可以把它递给一位设计师、一位 PM 或一位领域专家，让他们自己感受这个模型。页面背后的逻辑是一个小的纯模块——一个 reducer、一台状态机、一组函数——保持不沾 DOM，好让验证过的版本直接抬进真实代码。
- **「这个该长什么样？」**——同一条路由上的几个**截然不同**的 UI 变体，可从一个浮动底栏和一个 `?variant=` URL 参数切换。变体必须在结构上分歧，而非颜色；三个微调过的卡片网格是墙纸，不是原型。它们尽可能在一个真实页面里、对着真实数据和真实密度渲染，因为在真空里评判的变体总是看起来不错。

两者都把状态保持在内存里、以无需思考起步、并在每一步之后给你看完整状态。你一发现自己在给其中一个加固——加一个测试、接上真实数据库、为一个你稍后或许想要的情况做泛化——你就已经不在做原型了。

## 原型是一手来源

一个完成的原型留下两样东西，而它们去往不同的地方。

**答案**——裁决加上它定夺的那个问题——被持久地捕获：一条提交信息、一份 ADR、实现 issue。那是 main 分支保留的，被折进真实代码。

**原型**是答案由此得来的可运行证据，且它不被删除。它也不属于 main——那里没有什么要维护，而它腐坏得快——所以它被提交到 main 之外一个一次性的 `prototype/<name>` 分支上，从不合并，并在实现 issue 上留下一个指向该分支的[上下文指针](https://www.aihero.dev/ai-coding-dictionary/context-pointer)。Main 保持干净；探索则对下一个接手这项工作的人保持可寻、可重跑。

## 常见问题

**等等——原型不是本该被删掉吗？**
不再是了。以前是：构建它、保留答案、扔掉代码。对此最尖锐的反对从来不关乎速度——而是*下一次[会话](https://www.aihero.dev/ai-coding-dictionary/session)谁接手这项工作，他们有什么可依凭？*一份原型的散文摘要丢掉了让它有说服力的那样东西。所以原型现在被当作[一手来源](https://www.aihero.dev/ai-coding-dictionary/primary-source)对待：它落在 main 之外一个 `prototype/<name>` 分支上，实现 issue 指向它。改变的是代码住在哪里，而非那份训练——它仍然从不合并进 main。

**它以前构建一个终端应用。那去哪了？**
逻辑分支现在改为产出一个可分享的单一 HTML 文件。一个终端应用只能由克隆了仓库并装了运行时的人来驱动，这恰恰排除了原型所需要其意见的那些人——设计师、PM、以及知道状态模型该有何含义的领域专家。一个双击就能打开、且经得起邮件转发的自包含文件谁都能驱动。其下的纯逻辑模块未变，仍然是抬进真实代码的那部分。

**一个代理在我本该实现的时候叫我 `/prototype`。**
已知，且这是个命名问题。`prototype` 是一个通用、诱人的词，对一个不了解流程的代理来说，一旦工单存在它就读起来像「显而易见的下一步」，所以即便设计已在对话中完全敲定，它也会被按名推荐。如果你已经知道要构建什么，下一步是逐工单 `/implement`。只有当一个具体的设计问题确实悬而未决、且交谈解决不了它时才使用原型。

**我该不该在构建任何生产功能之前先给整个应用做原型——比方说，为了向潜在客户演示？**
那是一个披着这个技能名字的不同产物。这里的原型被限定在一个问题上，而「整个应用是什么」不是一个问题。一个全应用原型没有天然的停止点，所以它会靠惯性变成生产应用：清理那一遍永远不发生，而在原型规则下写的代码——没有测试、没有错误处理——最终摆到了用户面前。如果你需要一个销售演示，就刻意把它作为演示来构建，并明确其中没有一处是生产的。如果你需要定夺一个设计问题，就把它砍到那个问题上。

**我怎么在它自己的会话里运行它？**
一个原型住在它自己的目录里，并生成大量你不想要在提出问题的那个线程里的[上下文](https://www.aihero.dev/ai-coding-dictionary/context)，所以在别处运行它、只带回答案。[handoff](https://aihero.dev/skills-handoff) 是双向的桥梁。

**这难道不是烧 token 最快的方式吗？**
可以是，如果你给本可以靠交谈回答的问题做原型，或者让一个原型漫延到整个功能。要紧的比较不是 token 对零；而是 [token](https://www.aihero.dev/ai-coding-dictionary/token) 对构建错误的状态模型、并在它已有生产调用者之后才发现。把问题保持狭窄、把运行保持简短，花费就保持成比例。

## 它生效的标志

- 你能用一句话说出原型为回答什么问题而存在——而且它写在演示的顶部，不只是在你脑子里。
- 一个不读代码的人能驱动逻辑演示。他们打开文件、在一个演练标签页里按按钮，并用自己的话描述所见。
- 有人说「等等，那不该可能」或「咦，我以为是 X」。那是*想法*里的一个 bug，而这正是全部意义所在。
- UI 变体在布局和信息层级上分歧，而不只是颜色和文案——而你得到的反馈是「B 的页头配 C 的侧栏」。
- 它在一次坐下里被回答。如果一天后你还在构建它，那问题就太大了；拆分它。
- 结束时，main 里包含决定而没有原型的任何部分，而实现 issue 指向仍持有它的那个分支。

## 它的位置

`prototype` 是一个**随时可用的独立技能**——你跳进它去定夺一个设计问题，然后再跳出来——它也是另一个技能赖以运行的机件。

它最大的消费者是 [wayfinder](https://aihero.dev/skills-wayfinder)。一张 wayfinder 地图由**决策工单**构成，而 `prototype` 是一个工单可以是的四种类型之一：当阻塞问题是「这该长什么样」或「它该如何行为」、而任何讨论都解决不了时所用的那一种。Wayfinder 通过造出一个具体的、可供回应的东西来提升一场模糊讨论的保真度，而这个技能就是那个具体之物如何被构建出来的。一个原型工单靠答案被解决，而原型作为一项资产从地图上被链接。

其他邻居在它的上游和下游。[grill-me](https://aihero.dev/skills-grill-me) 和 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 回答可盘问的问题；不可盘问的那些改为来到这里，而那一行答案再回到访谈里。下游，一个验证过的状态模型或 UI 方向成为 [to-spec](https://aihero.dev/skills-to-spec) 的敲定输入，后者可以内联原型产出的那段富含决策的片段，而非用散文描述它。至于其他任何事，[ask-matt](https://aihero.dev/skills-ask-matt) 会在整套技能之间为你路由。
