## 它做什么

`wizard` 生成一个交互式 bash 脚本，一步一步引导一个人走过一段手动流程——接线第三方服务、运行一次性的迁移、把一个项目从状态 A 挪到状态 B。它打开每个 URL、说明该点什么、复制什么，捕获返回的东西，并把它写进 `.env` 文件和 GitHub Actions secret。

[agent](https://www.aihero.dev/ai-coding-dictionary/agent) 写这个脚本；它从不运行它。你运行，在你自己的机器上。所以一个 wizard 不是一份你去照做的指令清单——它是一个驱动流程并持有状态的程序，而你的部分是点击、粘贴、按回车。

## 何时使用它

你可以输入 `/wizard`，而 agent 也能自己去调用它。当它撞上一个你必须采取的步骤时——一个它无法铸造的密钥、一个它无法点击的仪表盘——它给你构建一个 wizard，而非把指令写进会滚走的聊天里。

当下一个阻塞你的东西是一趟穿过仪表盘的旅程时，使用它：

| 情况 | wizard 做什么 |
| --- | --- |
| 一个新开发者在应用启动前需要配置六个服务 | 按顺序打开每个仪表盘、捕获密钥、把它们写到 `.env` 和 CI |
| 一次性迁移需要按特定顺序翻转开关 | 把不可逆的步骤排在确认门之后 |
| 一个项目必须一次性地从状态 A 挪到状态 B | 走过那次转换并报告它无法做到的部分 |
| 你正要把那些步骤写进一个 README | 改为写一个可执行的版本，它不会那么悄无声息地腐烂 |

别用它来*决定*构建什么；那件事的工具是 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 和 [to-spec](https://aihero.dev/skills-to-spec)。

## 前置条件

生成一个不需要任何东西。它写的 wizard 在 bash 上运行，并在某个阶段设置一个 GitHub secret 或 variable 时使用 `gh`。如果 `gh` 缺失或未认证，那个阶段变成一个警告，收尾摘要告诉你要手动设置什么，而不是让运行失败。

## 阶段

一个**阶段**是一块屏幕上的一个聚焦任务。脚本在阶段之间清空终端，所以一个溢出屏幕的阶段会丢掉滚走的那部分。你按依赖顺序编写阶段并设置 `TOTAL_STAGES`，它驱动进度显示。

范围界定发生在写下一行之前。这个[技能](https://www.aihero.dev/ai-coding-dictionary/skill)读取仓库而非冷启动地询问：`.env*`、`docker-compose*`、框架配置、以及 `.github/workflows/` 里每一个 `secrets.*` / `vars.*` 引用——那些每一个都是 wizard 必须产出的一个值。然后它给你看有序的阶段列表以确认，只有在那之后才把每个阶段映射到一个人所遵循的确切路径（"Dashboard → Developers → API keys → Reveal test key → copy"）。在它不知道当前 UI 的地方，它问你或查文档，而非发明点击。

对每个捕获的值，范围界定敲定它落在哪里：

| 目的地 | 何时 |
| --- | --- |
| 只写 `.env` | 本地开发需要它，CI 不需要 |
| GitHub secret | CI 读它，而且它是敏感的 |
| GitHub variable | CI 读它，而且它是公开的 |
| `.env` 和一个 secret 都写 | 本地开发和 CI 都需要它 |
| 哪里都不写 | 那个阶段是一个纯动作——翻转一个开关、升级一个套餐 |

## 模板已经解决了 UX

这个[模板](https://github.com/mattpocock/skills/blob/main/skills/engineering/wizard/template.sh)交付整个体验：带剩余时间的进度、确认门、包括 WSL 在内的跨平台 URL 打开、secret 的隐藏输入、幂等的 `.env` upsert、`gh secret` / `gh variable` 写入、以及一份它不得不跳过的一切的收尾摘要。`STAGES` 标记以上的一切都是一个固定的库，在每个 wizard 里都相同，从不手工编辑。这个一致性正是重点。你的活只是界定流程的范围并编写它的阶段。

写一个 wizard 的 agent 从不端到端地运行它，因为它打开浏览器并等待人的输入。它改为静态地验证：`bash -n`、在可用的地方用 `shellcheck`、以及追踪每个值都落在范围界定所说的地方、每个 `set_secret` 名字都与 CI 里一个真实的 `secrets.*` 引用相符。据此设定你的预期——第一次运行是你的，而那次运行就是测试。

## 默认短暂

| 你有什么 | 拿脚本怎么办 |
| --- | --- |
| 一次性迁移、一次个人设置、一次你永不重复的转换 | 把它存到一个 scratch 或 `scripts/` 路径、运行它、删掉它 |
| 一条仓库上的下一个人也会需要的设置路径 | 提交它并从 README 链接它，好让他们运行脚本而非重新问一个 agent |

## 常见问题

**我的 API 密钥会进到模型的上下文里吗？**

不会。agent 写一个脚本；它不运行它。你自己运行脚本，而它用隐藏的终端输入捕获密钥并把它直接写到 `.env` 或 `gh secret`。wizard 是一个 CLI，而模型不与它相连。有一条告诫：那对 wizard 在运行时捕获的值成立。如果你在界定流程范围时把一个密钥粘进聊天，它就和任何其他粘贴的文本一样在[上下文](https://www.aihero.dev/ai-coding-dictionary/context)里。

**我能回去修正一个我敲错的值吗？**

运行中途不能。没有后退按钮——阶段向前运行，而在阶段 3 上一个错误答案意味着 Ctrl-C 并重新运行。重新运行按设计是廉价的：任何已经写到 `.env` 的值都作为一个默认被提供回来，所以你按回车穿过你做对的那些阶段、只重敲那个错的。这在发布周就被提出、此后没有被关闭："爱它！不过有一件事——有没有办法回去纠正你输入过的东西？"

有一个相关的未解决 bug。一个 `ask` 提示里的方向键插入 `^[[D` / `^[[C` 而非移动光标，因为那个提示用 `read -r` 而非 Readline（[issue #741](https://github.com/mattpocock/skills/issues/741)）。退格键管用；方向键不管用。删回到那个错处，而非把光标移进它。

**它知道我已经设置好了什么吗？**

部分知道，而且比发布时的反应所假设的少。它在询问之前读仓库——你的 `.env` 文件、`docker-compose`、框架配置、CI 里的 `secrets.*` 引用——所以它界定范围到真正缺失的值，而非像一个 README 那样从零开始。它不做的是检查那个第三方服务。如果一个密钥存在于你的 `.env`，wizard 把它提供回来、回车保留它；如果你已经创建了 Stripe 账户但从没保存密钥，wizard 仍然把你送去仪表盘取它。

**它在工作流里坐在哪里——在 grilling 和规范之后？**

没有特定的地方。它是一个独立的，不是一个链条步骤。常见的猜测是 `/grill-with-docs → /to-spec → /wizard`，而那个序列没问题，但触发条件是一段手动流程冒出来，那可能在任何点发生：在你开始之前、构建中途、或者发布很久之后。它也作为一个发现工具起作用——界定范围会浮现一个任务隐藏的前置条件，比如你没想到的那三个 API 密钥，在你投入工作之前。

**它在 Claude Code 之外管用吗？**

产物无条件管用：它是一个纯 bash 脚本，它不在乎什么[框架](https://www.aihero.dev/ai-coding-dictionary/harness)生成了它。技能本身是模型调用的，所以它到处都被列出——在 Claude Code 里输入 `/wizard`、在 Codex 里输入 `$wizard`、或者就描述你卡住的那个设置。是模型调用的也让它避开 [#693](https://github.com/mattpocock/skills/issues/693)，那里 Claude 的桌面和网页界面把*用户调用*的技能从[模型](https://www.aihero.dev/ai-coding-dictionary/model)的列表里丢掉、并报告它们未安装。

**这以前不是用户调用的吗？**

是的。它现在是模型调用的，所以当 agent 撞上一个你必须采取的步骤时它会不经提示地去调用它。你以前能做的一切都没有停止工作——模型调用*增加*了 agent 的触达，它从不移除你的，所以 `/wizard` 的行为和它以前完全一样。变的是它退役掉的那个失败模式：agent 在构建中途撞上一堵凭据墙、把六个编号步骤倾倒进聊天让你手动照做。

**它以前在 `in-progress/` 里——现在在哪？**

`engineering/`，自 v1.2 起。它从 beta 桶毕业，现在随插件发布，所以它和其余推广集一起到来，而非需要单独安装。它的行为在毕业时没有改变。

## 它生效的标志

- 你被展示一个有序的阶段列表、以及每一个产出的值，并被要求确认——在任何脚本存在之前。
- 每个 URL 都在那一页的值被询问之前被打开。你从不被要求粘贴一个你还没被送去取的东西。
- secret 是盲打的。没有敏感的东西回显进你的滚动缓冲区。
- 每个阶段都装得进一块屏幕。没有你还需要的东西滚走。
- Ctrl-C 并重新运行会从你离开的地方接上，把已经保存的值作为默认提供。
- 最后一屏列出它写了什么，并单独列出它无法做到、需要你手动完成的东西。

## 它的位置

`wizard` 是一个随时可用的独立技能，坐在自动化停止、一个人必须点击的那条线上。它最近的邻居是 [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills)，因为两者都为把一个仓库弄进一个可工作状态而存在——那个配置这套技能，而 `wizard` 为其他一切生成一条设置路径。它也和 [implement](https://aihero.dev/skills-implement) 配对：当一次构建落地一个需要凭据或手动切换的功能时，wizard 就是人的那一半怎么完成的方式。当你不确定哪个技能适合当下时，[ask-matt](https://aihero.dev/skills-ask-matt) 为你做路由。
