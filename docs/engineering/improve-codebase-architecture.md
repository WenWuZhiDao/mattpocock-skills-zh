## 它做什么

`improve-codebase-architecture` 普查一个代码库以寻找**可加深的机会**——那些浅模块（一个几乎与它所隐藏之物一样复杂的接口）可以变成深模块的地方——把它们写成一份自包含的 HTML 报告，然后就你所选的那一个对你进行[盘问](https://www.aihero.dev/ai-coding-dictionary/grilling)。

它从不改动代码。整次运行产出你操作系统临时目录里的一个 HTML 文件和一场对话；重构本身稍后发生，在一个单独的[会话](https://www.aihero.dev/ai-coding-dictionary/session)里，通过正常的构建流程。这正是让它成为一次普查而非一个重构工具的原因，也是为什么这个技能值得在一个你还没准备好去碰的代码库上运行。

两道过滤器防止报告沦为通用的清理建议。每个候选者都得通过**删除测试**——移除这个模块会把复杂性集中到一个更小的接口背后，还是只是把它摊到各个调用者身上？只有「集中」的情况才配得上一张卡片。而且，除非你把它指向某个特定区域，否则它会先读近期提交历史，并把扫描偏向正在活跃变化的路径，理由是在没人碰的代码里加深是一次你永远兑现不了的重构。

## 何时使用它

你通过输入 `/improve-codebase-architecture` 来调用它——[代理](https://www.aihero.dev/ai-coding-dictionary/agent)不会主动使用它。

它位于构建循环之外——它不是主循环中的一步，而是你周期性运行、以排出更多改进代码库的工作的东西。它被使用的四种情境：

| 情境 | 如何使用 |
| --- | --- |
| 例行维护 | 每隔几天、或每当有空闲片刻时运行它，以阻止结构在功能之间腐坏。 |
| 大构建之前 | 把它指向[规格](https://www.aihero.dev/ai-coding-dictionary/spec)：「我们怎样才能让这次改动变得容易？」这是给它的最有效的提示。 |
| 棕地审计 | 在一个大的、无结构的或[凭感觉写出](https://www.aihero.dev/ai-coding-dictionary/vibe-coding)的仓库上运行它，弄清它实际处于什么形状。 |
| 遗留测试工作 | 用它先找出缺失的接缝，然后再对着不可测的代码写测试。 |

它与同胞容易混淆之处：

- 要设计一个你已经选好的模块，用 [codebase-design](https://aihero.dev/skills-codebase-design)——那是工作台，这个是找出该往台上放什么的普查。
- 对于一整项大到无法装进一次会话的工作，用 [wayfinder](https://aihero.dev/skills-wayfinder)。
- 对于「这个特定的东西坏了」，用 [diagnosing-bugs](https://aihero.dev/skills-diagnosing-bugs)。当真正的发现是没有好接缝能把 bug 锁定时，它会交接回这里。

## 前置条件

运行它无需什么。如果 `CONTEXT.md` 和 `docs/adr/` 里的任何 ADR 存在，它会读它们，并在有它们时用你领域自己的名词说话——一个候选者读起来是「加深 Order intake 模块」，而非「重构 FooBarHandler」。

它写入两个地方。报告去 `<tmpdir>/architecture-review-<timestamp>.html`，在仓库之外。在盘问循环期间，它会往 `CONTEXT.md` 里添加或磨锐术语，如果该文件不存在则创建它，并提出把一个被否的候选者记录为 ADR，好让未来的运行不再重复建议它。

## 深度，以及那份猎取它的报告

这个技能围绕一个概念运转：**深度**。一个深模块把大量行为放在一个小而稳定的接口背后。一个浅模块通过一个几乎与其下代码一样宽的接口泄漏它的实现。报告是对浅薄的一次猎取——只为可测性而抽取的纯函数，而真正的 bug 却住在它们如何被调用之中（没有**局部性**）、跨其**接缝**泄漏的模块、一个你不打开五个文件就无法理解的概念——以及一个修复它的加深提案。

每个候选者是一张卡片：涉及的文件、摩擦、一个平实英语的解法、以**局部性**和**杠杆**表述的收益、一张前后对比图、以及一个强度徽章。

| 徽章 | 对你意味着什么 |
| --- | --- |
| `Strong` | 删除测试清晰通过，且摩擦真实。认真对待这些。 |
| `Worth exploring` | 貌似可行的加深，但收益取决于代码接下来往哪走。 |
| `Speculative` | 为完整性而浮现。这些大多可以安全忽略。 |

报告以一个 **Top recommendation** 结束——它会最先着手的那一个——然后技能停下并问你想探索哪个候选者。到那一刻什么都还没决定，也没有任何代码移动过。

## 你选了一个之后会发生什么

选一个候选者会就它开启一次[盘问](https://www.aihero.dev/skills-grilling)会话：约束、接缝背后坐着什么、哪些测试能存活、加深后的接口该长什么样。那次会话的产出是一个决定，而非一个差异。从那里起适用正常流程——把决定带进 [to-spec](https://aihero.dev/skills-to-spec)，然后 [to-tickets](https://aihero.dev/skills-to-tickets)，然后 [implement](https://aihero.dev/skills-implement)。

## 常见问题

**它就一个想法盘问了我一小时，而不是给我看选项。我能把那关掉吗？**

能——在调用时说明（「别盘问我，就给我看报告」）。这是这个技能最响亮的抱怨。一位用户直言：他喜欢它是「一个获得对改进的彻底分析的便利方式」，而在盘问循环被加上之后觉得它「近乎不可用」，报告说有些会话它提出一个单一解法然后问了「十个乃至上百个问题」。设计意图是报告先来、盘问只在你选好的候选者上开始，但更弱的[模型](https://www.aihero.dev/ai-coding-dictionary/model)会直接跳到就它想到的第一个想法访谈你。那个帖子里的报告因模型而剧烈不同，且这是一个开放 issue——技能还没有一个文档记录的无盘问模式。

**报告打开时是没有样式的原始 HTML，也没有图。发生了什么？**

报告从 CDN 加载 Tailwind 和 Mermaid，所以你打开它时需要网络访问，而当有东西拦住那些脚本时它会悄无声息地坏掉。归档的案例是一个安全钩子要求 SRI 哈希：代理加上了它们，CDN 给浏览器提供的字节与用来计算哈希的 `curl` 所得的不同，于是浏览器拦住了脚本。离线和锁定的环境撞上同一堵墙。代理看不到这个，因为它从不渲染页面。绕行之法是要求内联 CSS 和手工搭的 SVG 图，而非那套 CDN 脚手架。这是一个开放 issue，也是一个真实的粗糙边缘。

**它给了我十二个候选者。我在同一次会话里逐个处理，还是开一个新的？**

每次会话一个候选者。在一场对话里逐个处理好几个，会把报告、盘问、领域模型编辑和代码改动一下子全塞满[上下文窗口](https://www.aihero.dev/ai-coding-dictionary/context-window)。报告只住在一个临时文件里，所以携带候选者本身而非那个文件：选一个、盘问它、把决定带进 `/to-spec`，并把其余的变成你稍后能独立拾起的[工单](https://www.aihero.dev/ai-coding-dictionary/ticket)。把选定的改进放进一份规格，而不是直接去实现。这是一个反复出现的问题，而技能本身没有文档记录的工作流。

**我该怎么提示它？**

带着你接下来要构建的东西来提示。当一次大构建即将到来时，把它指向规格并问「我们怎样才能让这次改动变得容易？」一次不加提示的运行会自行扫描热点，这对例行维护没问题，但指明一个方向才是让报告可操作的关键。

**它在一个大的遗留代码库上有用吗？**

部分有用。它在缺乏一致结构的大型现有代码库上很强，且是任何一次性结构设置之后推荐的维护机制。诚实的对冲：拥有真正失控项目的用户报告它「帮了一点，但似乎仍不够劲」，而一位有着八年遗留代码库的开发者报告模型在打转，而同一个技能在一个整洁的仓库上却能产出干净的图。目前还没有针对那种情况的专门 `/refactor` 技能。如果代码库完全没有共享词汇，先用 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 建立一套，往往能让这个技能的产出好得多。

**这跟 `/codebase-design` 有什么不同？**

`/codebase-design` 是一份参考，而非会话驱动器。它提供词汇——模块、接口、深度、接缝、适配器、杠杆、局部性——而这个技能借用它。把一个全新代理指向 `/codebase-design` 当作要「做」的事是一个已知的失败：由于它自身没有可遵循的流程，代理会发明一个、重新探索代码，并在问你任何问题之前跑很长时间。用这个技能来驱动；消费那一个。

**它会不会告诉我代码库没问题？**

很少，而你该带着这一点上路。这个技能是为输出发现而造的，所以这个框架把它推向产出候选者、而非得出没什么不对的结论。强度徽章就是那道防线——一份所有东西都是 `Speculative` 的报告，就是这个技能在用它唯一知道的方式告诉你它什么都没找到。

**它在 Codex 或另一个载体里有用吗？**

部分有用。探索步骤直接点名 Claude Code 的 `Agent` 工具加 `subagent_type=Explore`，所以一个没有那个工具的[载体](https://www.aihero.dev/ai-coding-dictionary/harness)可能会跳过并行探索、而非代之以自己的。技能仍照跑；只是扫描没那么彻底。一个载体中立的重写已被提议但未合并。

**我到底如何用 TypeScript 实现深模块？**

技能没有附带一个好答案。反复出现的请求是要一份 `TYPESCRIPT.md`，为这些原则给出具体的文件和模块布局，而它并不存在。技能会告诉你一个加深归属何处、以及接缝背后该坐什么；把那翻译成一个包或目录结构，眼下是你自己的事。

## 它生效的标志

- 候选者点名你领域的概念，而非发明的类名——是「Order intake 模块」，而非「FooBarHandler」。
- 候选者聚集在你近期编辑过的文件里，而非仓库中休眠的角落。
- 运行期间没有代码改动。唯一的新文件是你临时目录里的那份 HTML 报告。
- 它在报告之后停下并问你想要哪个候选者，而不是自行继续。
- 每张卡片把收益解释为局部性或杠杆，并说出哪些测试变简单了——而不只是「这更干净了」。
- 因一个经久的理由否掉一个候选者，会换来一个记录 ADR 的提议，好让下次运行不再重复建议它。

## 它的位置

`improve-codebase-architecture` 是**周期性维护**——每隔几天运行它，在任何链条之外，用来排出工作而非做工作。它的邻居是 [codebase-design](https://aihero.dev/skills-codebase-design)（它拥有每个候选者据以书写的深度与接缝词汇）、[grilling](https://aihero.dev/skills-grilling)（一旦你选好一个候选者，它就走一遍决策树）、以及 [domain-modeling](https://aihero.dev/skills-domain-modeling)（在决定敲定时保持 `CONTEXT.md` 和 ADR 为最新）。它产出的是一个想法，该想法在 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 或 [to-spec](https://aihero.dev/skills-to-spec) 处重新进入主构建流程。对于哪个技能契合某个情境，[ask-matt](https://aihero.dev/skills-ask-matt) 是凌驾于整套技能之上的路由器。
