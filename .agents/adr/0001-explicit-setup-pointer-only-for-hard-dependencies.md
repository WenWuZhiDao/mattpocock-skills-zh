# 仅在硬依赖场景下显式指向 `/setup-matt-pocock-skills`

工程类技能依赖由 `/setup-matt-pocock-skills` 播种的按仓库配置（问题跟踪器、分诊标签词汇表、领域文档布局）。有些技能在缺少该配置时根本无法有意义地运作——它们必须发布到某个特定的问题跟踪器，或者应用某个特定的标签字符串。另一些技能只是用它来让输出更精准（词汇表、ADR 感知），即使没有它也能优雅降级。

我们把这些技能拆分为**硬依赖**和**软依赖**两类：

- **硬依赖**（`to-tickets`、`to-spec`、`triage`）——包含一句显式提示：_"……应当已经提供给你了——如果没有，请运行 `/setup-matt-pocock-skills`。"_ 缺少这个映射时，输出就是错的，而不仅仅是模糊。
- **软依赖**（`diagnose`、`tdd`、`improve-codebase-architecture`）——只在含糊的散文中提及"项目的领域术语表"和"你所触及区域的 ADR"。如果这些文档不存在，技能依然能工作，只是输出没那么精准。

这样的拆分让软依赖技能保持轻量（占用更少 token），并避免把 setup 指针机械地照搬到那些它并不起关键作用的地方。
