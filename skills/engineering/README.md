# Engineering（工程）

我每天用于代码工作的技能。

- **[diagnose](./diagnose/SKILL.md)** — 针对疑难 bug 和性能退化的严谨诊断循环：复现 → 最小化 → 提出假设 → 插桩 → 修复 → 回归测试。
- **[grill-with-docs](./grill-with-docs/SKILL.md)** — 拷问式会话，用现有领域模型挑战你的计划，打磨术语，并就地更新 `CONTEXT.md` 和 ADR。
- **[triage](./triage/SKILL.md)** — 通过一套分诊角色状态机对 issue 进行分诊。
- **[improve-codebase-architecture](./improve-codebase-architecture/SKILL.md)** — 在代码库中寻找加深模块的机会，由 `CONTEXT.md` 中的领域语言和 `docs/adr/` 中的决策提供参考。
- **[setup-matt-pocock-skills](./setup-matt-pocock-skills/SKILL.md)** — 搭建每个仓库各自的配置（issue tracker、分诊标签词表、领域文档布局），供其他工程类技能使用。
- **[tdd](./tdd/SKILL.md)** — 测试驱动开发，采用红-绿-重构循环。一次一个垂直切片地构建功能或修复 bug。
- **[to-issues](./to-issues/SKILL.md)** — 用垂直切片把任何计划、规格或 PRD 拆分成可独立认领的 GitHub issue。
- **[to-prd](./to-prd/SKILL.md)** — 将当前对话上下文转化为 PRD，并作为 GitHub issue 提交。
- **[zoom-out](./zoom-out/SKILL.md)** — 让 agent 拉远视角，对一段不熟悉的代码给出更宏观的上下文或更高层次的视角。
- **[prototype](./prototype/SKILL.md)** — 构建一个用完即弃的原型来充实设计——既可以是针对状态/业务逻辑问题的可运行终端应用，也可以是从同一路由切换的几种风格迥异的 UI 变体。
