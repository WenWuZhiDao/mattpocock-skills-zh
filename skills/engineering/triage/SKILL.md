# Triage（分诊）

将项目 issue 跟踪器上的 issue 推动通过一个由 triage 角色构成的小型状态机。

在 triage 过程中发布到 issue 跟踪器的每一条评论或 issue **都必须**以这条免责声明开头：

```
> *This was generated by AI during triage.*
```

## 参考文档

- [AGENT-BRIEF.md](AGENT-BRIEF.md) — 如何撰写可持久使用的 agent 简报
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md) — `.out-of-scope/` 知识库的运作方式

## 角色

两个**类别（category）**角色：

- `bug` — 有东西坏了
- `enhancement` — 新功能或改进

五个**状态（state）**角色：

- `needs-triage` — 维护者需要评估
- `needs-info` — 等待报告者提供更多信息
- `ready-for-agent` — 已完整描述，可供 AFK agent 处理
- `ready-for-human` — 需要人工实现
- `wontfix` — 不会处理

每个经过 triage 的 issue 都应当恰好带有一个类别角色和一个状态角色。如果状态角色之间发生冲突，先标记出来并询问维护者，然后再做其他任何事。

这些是规范角色名——issue 跟踪器中实际使用的标签字符串可能不同。这一映射应当已经提供给你——如果没有，请运行 `/setup-matt-pocock-skills`。

状态转换：一个无标签的 issue 通常先进入 `needs-triage`；从那里它会移动到 `needs-info`、`ready-for-agent`、`ready-for-human` 或 `wontfix`。`needs-info` 在报告者回复后回到 `needs-triage`。维护者可以在任何时候覆盖这一流程——对看起来不寻常的转换要先标记并询问，再继续。

## 调用

维护者调用 `/triage` 并用自然语言描述他们想要什么。解读该请求并采取行动。示例：

- "给我看看任何需要我关注的东西"
- "我们来看看 #42"
- "把 #42 移到 ready-for-agent"
- "有什么是 agent 可以接手处理的？"

## 展示需要关注的内容

查询 issue 跟踪器，并呈现三个分组，最旧的在前：

1. **无标签（Unlabeled）** — 从未被 triage 过。
2. **`needs-triage`** — 评估进行中。
3. **`needs-info` 且自上次 triage 笔记以来有报告者活动的** — 需要重新评估。

展示每个分组的数量，以及每个 issue 的一行摘要。让维护者来挑选。

## Triage 某个具体的 issue

1. **收集上下文。** 阅读完整的 issue（正文、评论、标签、报告者、日期）。解析任何先前的 triage 笔记，这样你就不会重复询问已解决的问题。使用项目的领域术语表探索代码库，尊重该区域内的 ADR。阅读 `.out-of-scope/*.md`，并把任何与本 issue 相似的先前驳回结论浮现出来。

2. **给出建议。** 把你的类别和状态建议连同理由告诉维护者，外加一份与该 issue 相关的简短代码库摘要。等待指示。

3. **复现（仅限 bug）。** 在任何提问核对之前，尝试复现：阅读报告者的步骤，追踪相关代码，运行测试或命令。报告发生了什么——成功复现（附代码路径）、复现失败，或细节不足（一个强烈的 `needs-info` 信号）。一次确认的复现能让 agent 简报强得多。

4. **提问核对（如有需要）。** 如果该 issue 需要充实，运行一次 `/grill-with-docs` 会话。

5. **应用结果：**
   - `ready-for-agent` — 发布一条 agent 简报评论（[AGENT-BRIEF.md](AGENT-BRIEF.md)）。
   - `ready-for-human` — 结构与 agent 简报相同，但注明为什么它不能被委派（判断性决定、外部访问、设计决策、手动测试）。
   - `needs-info` — 发布 triage 笔记（见下方模板）。
   - `wontfix`（bug）— 礼貌地解释，然后关闭。
   - `wontfix`（enhancement）— 写入 `.out-of-scope/`，从一条评论中链接到它，然后关闭（[OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)）。
   - `needs-triage` — 应用该角色。如果有部分进展，可选地附一条评论。

## 快速状态覆盖

如果维护者说 "把 #42 移到 ready-for-agent"，就信任他们并直接应用该角色。确认你即将做的事（角色变更、评论、关闭），然后行动。跳过提问核对。如果在没有提问核对会话的情况下移到 `ready-for-agent`，询问他们是否想写一份 agent 简报。

## Needs-info 模板

```markdown
## Triage Notes

**What we've established so far:**

- point 1
- point 2

**What we still need from you (@reporter):**

- question 1
- question 2
```

把提问核对过程中解决的所有内容都记录在 "established so far" 下面，这样工作成果就不会丢失。问题必须是具体且可操作的，而不是 "请提供更多信息"。

## 恢复一次先前的会话

如果该 issue 上存在先前的 triage 笔记，阅读它们，检查报告者是否已回答了任何未决问题，并在继续之前呈现一幅更新后的全貌。不要重复询问已解决的问题。
