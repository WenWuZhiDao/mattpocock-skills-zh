# Domain Docs（领域文档）

工程类技能在探查代码库时应如何消费本仓库的领域文档。

## 在探查之前，先读这些

- 仓库根目录下的 **`CONTEXT.md`**，或
- 如果存在，仓库根目录下的 **`CONTEXT-MAP.md`** —— 它为每个上下文指向一个 `CONTEXT.md`。读取与当前主题相关的每一个。
- **`docs/adr/`** —— 阅读涉及你即将开展工作的领域的 ADR。在多上下文仓库中，也要检查 `src/<context>/docs/adr/` 中按上下文限定的决策。

如果这些文件中有任何不存在，**静默继续**。不要标记它们的缺失；不要建议预先创建它们。生产者技能（`/grill-with-docs`）会在术语或决策真正被定下来时惰性地创建它们。

## 文件结构

单上下文仓库（大多数仓库）：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

多上下文仓库（根目录下存在 `CONTEXT-MAP.md`）：

```
/
├── CONTEXT-MAP.md
├── docs/adr/                          ← 系统级决策
└── src/
    ├── ordering/
    │   ├── CONTEXT.md
    │   └── docs/adr/                  ← 上下文特定决策
    └── billing/
        ├── CONTEXT.md
        └── docs/adr/
```

## 使用词汇表中的术语

当你的输出命名某个领域概念时（在 issue 标题、重构提案、假设、测试名称中），使用 `CONTEXT.md` 中定义的术语。不要漂移到词汇表明确要避免的同义词上。

如果你需要的概念还不在词汇表中，那是一个信号 —— 要么你在发明项目并不使用的语言（请重新考虑），要么存在真正的空缺（记下来交给 `/grill-with-docs`）。

## 标记 ADR 冲突

如果你的输出与现有的 ADR 相矛盾，请显式地指出来，而不是悄悄地覆盖它：

> _与 ADR-0007（事件溯源订单）相矛盾 —— 但值得重新讨论，因为……_
