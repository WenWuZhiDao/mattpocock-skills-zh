# 学习记录格式

学习记录位于 `./learning-records/`，采用顺序编号：`0001-slug.md`、`0002-slug.md` 等。惰性创建该目录——只在写第一条记录时才创建。

它们是教学版的 ADR：记录那些不显而易见的经验、关键洞见，以及已陈述的先验知识，这些都会引导未来的会话。它们用于计算最近发展区。

## 模板

```md
# {所学到或所确立内容的简短标题}

{1-3 句话：学到了什么（或确立了什么先验知识），以及它为什么对未来的会话重要。}
```

这就是全部格式。一条学习记录可以只是一个段落。其价值在于记录*这件事现在已知*以及*为什么它会改变接下来该教什么*——而不在于填满各个小节。

## 可选小节

只在这些小节确实增添价值时才包含。大多数记录不需要它们。

- **Status** 前置元数据（`active | superseded by LR-NNNN`）——当较早的理解被证明有误并被替换时有用。
- **Evidence** ——用户如何展示了这种理解（答对了一个问题、完成了一个练习、引用了过往经验）。当该论断日后可能被重新审视时有用。
- **Implications** ——这为未来的会话解锁或排除了什么。当不显而易见时值得记录。

## 编号

扫描 `./learning-records/` 找出现有的最大编号，加一。

## 何时写学习记录

当以下任一情况成立时，写一条：

1. **用户展示了对某件非平凡事物的真正理解** ——不只是接触过，而是有证据表明他们能正确运用该概念。这为接下来该教什么设定了新的下限。
2. **用户透露了先验知识** ——“我已经知道 X 了。”记下来，以便未来的会话不再重教。同时记录所声称的*深度*。
3. **一个误解被纠正** ——用户先前相信某个错误的东西，现在明白了为什么错。这些价值很高：它们能预测相关主题中未来的绊脚石。
4. **使命因学习而发生了转变** ——用户发现自己在意的东西与原先以为的不同。交叉链接到 [[MISSION.md]] 并更新它。

### 哪些*不*符合条件

- 仅仅被覆盖到的材料。覆盖不等于学会。等待证据。
- 任何已在 [[GLOSSARY.md]] 中作为术语定义被简洁记录的内容。不要重复。
- 逐会话的活动日志。学习记录不是日记——它们是决策级别的洞见。

## 取代（Supersession）

当一条较晚的记录与较早的记录相矛盾（用户的理解加深或得到纠正）时，把旧记录标记为 `Status: superseded by LR-NNNN`，而不是删除它。理解如何演变的历史本身就是有用的信号。
