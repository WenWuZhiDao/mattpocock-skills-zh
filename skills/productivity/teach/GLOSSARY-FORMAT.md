# GLOSSARY.md 格式

`GLOSSARY.md` 是这个教学工作区的规范语言。所有讲解、练习和学习记录都应遵循它的术语。构建它本身就是学习的一部分：把一个概念压缩成一个紧凑的定义，正是用户理解了它的证据。

## 结构

```md
# {主题} Glossary

{对该术语表所涵盖主题的一两句描述。}

## Terms

**Hypertrophy**:
由机械张力和代谢压力在反复训练中驱动的肌肉增长。
_Avoid_: Bulking, getting big

**Progressive overload**:
随时间系统性地增加对肌肉的需求——通过负荷、训练量或强度。
_Avoid_: Pushing harder, levelling up

**RPE (Rate of Perceived Exertion)**:
对一组动作感觉有多吃力的 1–10 自评分，10 表示力竭，8 表示还剩两次重复。
_Avoid_: Effort score, intensity rating
```

## 规则

- **只在用户理解某术语时才添加它。** 术语表是已压缩知识的记录，而不是用户用来学习的字典。如果用户刚被引入某个概念，等到他们能正确运用它后再把它收录进来。
- **要有主见。** 当同一个概念有多个词时，挑最好的一个，把其余的列为应避免的别名。语言就是这样被压缩的。
- **保持定义紧凑。** 一两句话。定义这个术语*是什么*，而不是它做什么或怎么做。
- **在定义内部使用术语表自身的术语。** 一旦某个术语进入术语表，就在任何地方都优先使用它——包括在其他定义内部。这正是让复杂术语日后更易理解的原因。
- **当出现自然聚类时，按子标题分组**（例如 `## Anatomy`、`## Programming`）。当术语彼此相关时，扁平列表也没问题。
- **明确标出歧义。** 如果某个术语在更广的领域里被宽泛使用，注明其解决方案：“在本工作区中，‘set’ 始终指工作组——热身组单独追踪。”
- **随着理解加深而修订。** 用户在第一周写下的定义，到第六周可能就错了。就地更新；不要留下过时的条目。
