# 术语表 —— 打造出色的技能

关于“什么让一个技能出色”的领域模型。技能之所以存在，是为了从随机系统中拧出确定性；根本美德是**可预测性**，下面每个术语都是作用于它的一根杠杆。这是 [`writing-great-skills`](SKILL.md) 所披露的参考资料。

这些术语按维度分组：**触发**（技能如何被触及）、**信息层级**（其内容如何排布）、**引导**（agent 的运行时行为如何被塑造）以及**修剪**（如何让它保持精简）。每个**失败模式**都紧挨着能治愈它的那根杠杆，并标记为 _失败模式_。

任何定义中的**加粗术语**本身也都在本术语表中有定义；按其标题查找。

## 可预测性 (Predictability)

技能让 agent 在每一次运行中都以相同的_方式_行事的程度——是相同的过程，而非相同的输出（一个头脑风暴技能应当_可预测地_发散；它的 token 各不相同，它的行为却始终如一）。这是其他每个术语所服务的根本美德——成本和可维护性是它的症候，而非与它抗衡的对手。

_避免_：一致性、可靠性、健壮性、输出确定性

## 触发 (Invocation)

技能如何被触及——以及你为这个选择所付出的两种负载。

### 模型触发 (Model-Invoked)

保留了 **description** 字段的技能，因此 agent 能看到它并自主触发——而人类仍然可以输入它的名字，所以模型触发始终_包含_用户可达。不存在只限模型的状态：description 只会_增加_ agent 的可发现性，绝不会移除人类的可达性。它为那份可发现性付出永久的**上下文负载**——每一轮都要付。它可被其他技能触及，因为使它对 agent 可发现的那个 description 同时也使它可被调用。一个内容全是**参考资料**的模型触发技能，也是共享参考资料的一个归处：另一个技能可以调用它，于是多个技能都需要的参考资料就集中住在一处。只有当 agent 必须靠自己触及某技能时，才选择模型触发；如果它除了手动就从不触发，那就删掉 description，不付任何上下文负载。

_避免_：能力、工具、本领

### 用户触发 (User-Invoked)

一个被剥去 **description** 的技能——对 agent 不可见，只能由人类输入其名字来触及（用户_专属_，而**模型触发**是用户_与_ agent 皆可）。它以 agent 可发现性换来零**上下文负载**。因为没有 description，除了人类没有任何东西能触及它：没有别的技能能触发它。

_避免_：流程、工作流、命令

### 描述 (Description)

技能的机器可读触发器，也是**模型触发**技能被迫始终保持加载的那一个**上下文指针**。它单是存在_就_定义了触发这一维度：保留它，技能便是模型触发（并可被其他技能触及）；删除它，技能便成为**用户触发**，只能被人类触及。它是模型触发技能之**上下文负载**的来源。

_避免_：frontmatter、摘要

### 上下文指针 (Context Pointer)

一个持于 agent 上下文中的引用，它指名某份不在上下文里的材料，并编码了触及它的条件。**description** 是最顶层的上下文指针（上下文窗口 → 技能）；指向被披露文件的指针是下一层的同一种对象。是它的措辞——而非它所指的目标——决定 agent _何时_触及，以及_有多可靠_。一个必备目标却配了一个措辞薄弱的指针，就是一个方差 bug：先修措辞，只有在磨锐它仍失败时，才把材料内联进来。

_避免_：链接、引用、导入

### 上下文负载 (Context Load)

一个**模型触发**技能施加于 agent 上下文窗口的成本——它的 **description** 始终被加载，既花 token 又花注意力。这是**用户触发**技能靠没有 description 而免除的东西，也是拆分出更多模型触发技能的刹车。

_避免_：token 成本、上下文膨胀

### 认知负载 (Cognitive Load)

一个**用户触发**技能施加于人类的成本——他们必须记在脑中的东西：有哪些技能存在，以及何时该取用哪一个（人类就是那个索引）。这是**模型触发**靠对 agent 可发现而免除的东西，也是拆分出更多用户触发技能的刹车。它不是要去最小化的成本：它是人类能动性的代价，是某些技能保持用户触发的理由。在人类判断重要之处花它；在无关紧要之处去掉它。

_避免_：人类索引、负担、开销

### 路由技能 (Router Skill)

一个**用户触发**技能，其职责是指向你其他的用户触发技能——为每一个命名并说明何时取用它——好让人类只需记住一个技能，而不是许多个。它只能提示，绝不能触发它们：用户触发技能没有 **description**，所以除了人类没有任何东西能触及它们。它是用户触发技能繁衍过多时，对**认知负载**的解药。

_避免_：调度器、菜单、注册表、索引、路由流程

### 粒度 (Granularity)

你把技能划分得多细。更细的划分要花掉两种负载之一：更多**模型触发**技能花**上下文负载**（更多 description 挤占窗口、争抢注意力）；更多**用户触发**技能花**认知负载**（人类要记住并取用的更多）。有两种切法指导划分。按**触发**切：在你有一个独特的**引导词**去触发它时，切出一个模型触发技能——一个你在提示里确实会用的触发词。按**序列**切：当某个步骤的**后续步骤**需要被隐藏时，切开一串**步骤**，因为把它隔离在自己的上下文里能清掉其后的内容。当心相反的做法：合并序列会把每个步骤的后续步骤暴露给其后的内容，招致过早完成。

_避免_：切块、模块化

## 信息层级 (Information Hierarchy)

技能的内容如何排布，以及每一块在阶梯上处于多低的位置。

### 信息层级 (Information Hierarchy)

技能的内容按 agent 需要它有多即时来排序——这是一架阶梯，由两种切分产生：在文件内还是在指针之后，以及是步骤还是参考资料。各级横档：

- **步骤** — 文件内，主要
- **参考资料**，文件内 — 次要
- **参考资料**，被披露的 — 在一个**上下文指针**之后

一个没有**步骤**的技能只用底下两档——往往是一组名副其实的平级同侪（例如某项评审的每条规则都在同一档上），这是一种恰当的排布，而非坏味道。层级独立于触发方式：无论技能全是步骤、全是参考资料还是二者兼有，它都可以是模型触发或用户触发。当一个技能有步骤时，本应被披露却留在文件内的参考资料会把步骤埋没，让关注它们变成一场抛硬币——这是一根方差杠杆，不只是易读性问题。让阶梯的顶部保持清晰易读；凡能往下推的都往下推。

_避免_：结构、组织、布局

### 步骤 (Steps)

agent 所执行的有序动作——当技能有它们时，是其内容的主要层级，也是它在 SKILL.md 中挣得一席之地的部分。并非每个技能都有步骤：一个技能可以全是步骤（`tdd`）、全是**参考资料**（一项评审），或二者兼有，与触发方式无关。每个步骤都以一个**完成判据**收尾，或清晰或含糊。

_避免_：工作流、指令、编排

### 参考资料 (Reference)

agent 按需查阅的材料——定义、事实、参数、示例、条件性指令。当技能有**步骤**时它次于步骤；当技能没有步骤时它就是全部内容；或者它完全存在于任何技能之外——见**外部参考资料**。经由**上下文指针**触及，也是**渐进式披露**的首要候选对象。

_避免_：支持材料、文档、背景

### 外部参考资料 (External Reference)

存在于技能系统之外的**参考资料**——一个普通文件，没有 **description**、没有**步骤**、不可被调用——任何技能都可以指向它。它是那些无需自行触发的共享参考资料的归处，也是两个**用户触发**技能唯一能共用的归处，因为二者都没有 description，所以谁也无法触发对方。

_避免_：文档、资源、知识库

### 渐进式披露 (Progressive Disclosure)

把**参考资料**沿阶梯往下移——移出 SKILL.md、放到一个**上下文指针**之后——好让顶部保持清晰易读。它主要不是一种 token 优化；它是**信息层级**被守护的方式。由**分支**授权：披露只有部分分支需要的东西，内联每条路径都需要的东西，而如果某个指针在必备材料上触发得不可靠，就磨锐它的措辞，只有在那也失败时才把它拉回内联。

_避免_：惰性加载、切块

### 就近共置 (Co-location)

把 agent 同时需要的材料放在一处——一个概念的定义、规则和注意事项都归在同一个标题之下，而不是散落在文件各处——这样读到其中一部分就会把它的邻居一并带来。它是**信息层级**在文件内的搭档：层级排的是一块材料处于_多低_的位置；就近共置决定的是它一旦落位_旁边坐着什么_。一份**参考资料**的正确格式没有公式；判准是一个技能应当读起来像是为 agent 写的文档，而分组的材料读起来就是那样，散落的材料则不然。它与**重复**不同：重复是把同一个含义放在两处，而散落是把单一含义碎裂到多处。

_避免_：分组、聚类、内聚

### 蔓延 (Sprawl)

_失败模式。_ 一个单纯太长的技能——SKILL.md 里行数太多——与这些行是否陈旧或重复无关。即便一个全是活内容、全是独一无二内容的技能也会蔓延。它花掉可读性（agent 在能动手前要趟过更多内容，注意力也在这多余之处变薄）、可维护性（每多一行就多一行要保持**相关**）以及 token。解药是**信息层级**：把**参考资料**推到**上下文指针**之后，并按**分支**或序列拆分，好让每条路径只携带它需要的东西。它与**沉积**（长度源于陈旧的堆积）和**重复**（长度源于含义被重复）不同——蔓延就是长度本身，不论其成因。

_避免_：臃肿、长度、体积、啰嗦

## 引导 (Steering)

那些把 agent 的运行时行为朝**可预测性**方向塑造的杠杆。

### 分支 (Branch)

技能可以被触发的一种不同方式——技能所处理的一种情形——因此不同的运行会走它内部的不同路径。一个有许多步骤的技能可能承载许多分支；一个线性的技能则没有。

_避免_：路径、情形、分岔

### 引导词 (Leading Word)

一个紧凑的概念——也叫 _Leitwort_——它已经住在模型的预训练里，agent 在运行技能时会用它来思考。它以尽可能少的 token 编码一条行为原则，靠调动模型已经持有的先验来做到这一点（例如 _lesson_、_proximal zone of development_、_fog of war_、_tracer bullets_）。它作为一个 token 被重复，而非作为一个句子，会在整个技能里累积起一份分布式的定义，并锚定一整片行为区域。自造一个词也行——只要你把它定义清楚——但一个生造的词招不来任何先验：你在定义的 token 上付出的，正是一个预训练词免费给你的。先去找一个现成的词。

引导词双重服务于**可预测性**。在正文里它锚定**执行**——每当那个概念出现，agent 都伸手去取同一种行为，而在扁平的参考资料内部，它把注意力聚焦到某一类要留意的东西上，每次运行都招来对的检查。在 **description** 里它锚定**触发**——而且不只在技能内部：当同一个词也住在你的提示、你的文档和你的代码库里时，agent 会把那份共享语言与这个技能关联起来，从而更可靠地触发它。用你在想要这个技能时真正会用的那些引导词来撰写 description。

_避免_：关键词、术语、母题

### 完成判据 (Completion Criterion)

告诉 agent 一个工作单元已完成的条件——它据以判断的靶子。有两个属性使它成为一根杠杆，而不只是一种品质。它的**清晰度**（agent 能否分辨完成与未完成？）抵御**过早完成**——一个含糊的界线（“达成理解”）会让 agent 宣告完成并溜到下一步；这个维度需要_步骤_才咬得住，因为过早完成是一种步骤之间的失败。它的**要求量**（它索取多少）设定**底层功夫**——“每个被改动的 model 都有交代”会逼出彻底的工作，而“产出一份改动清单”则不会——而这个维度_不_受步骤束缚：它也能约束一片扁平的参考资料，这正是一个没有步骤的技能仍能带有一条穷尽性标准（“每条规则都已应用”）的方式。最强的判据既可检验又穷尽。

_避免_：完成条件、退出条件、停止规则

### 底层功夫 (Legwork)

agent 在单个步骤内幕后所做的工作——读文件、探索代码库、做改动、把自己需要的东西挖出来，而不是甩给用户。它住在步骤结构之下：从不被写成自己独立的一步，潜伏在措辞里，由 agent 而非技能来掌控。它是**后续步骤**那种跨步骤拉力的步骤内对应物。由一个**引导词**（_comprehensive_、_thorough_）或一个要求工作必须穷尽的**完成判据**抬高——包括应用于扁平参考资料的“要求量”维度，正是它驱使一个全是扁平参考资料的技能去覆盖它所有的横档。当那份要求缺席，或者**过早完成**把步骤截短时，它就变薄。

_避免_：范围、努力、勤勉、覆盖

### 后续步骤 (Post-Completion Steps)

紧跟在当前步骤之后的那些**步骤**。它们一旦可见，就把 agent 向前拽入**过早完成**——它看到得越多，拉力越强；防御办法是把步骤序列一分为二从而隐藏它们。

_避免_：地平线、战争迷雾、前瞻

### 过早完成 (Premature Completion)

_失败模式。_ 在当前步骤真正完成之前就结束它，因为 agent 的注意力从工作本身溜到了“已经完成”上。这是一种步骤之间的失败：它需要**步骤**才会发生——一个没有步骤的技能提前收手不是过早完成，而是在未被满足的要求下变薄的**底层功夫**。它是两股力之间的拔河：可见的**后续步骤**（向前的拉力）与**完成判据**的清晰度（阻力——一条锐利、可检验的界线撑得住；一条含糊的则让步）。模糊是其必要条件：一条锐利的界线不论多少后面的步骤可见都能抵抗拉力，所以一个从不赶工的步骤无需防守。有两根杠杆能撑住一个会赶工的步骤，但要按次序取用：**先磨锐界线**——这是局部且廉价的。只有当判据不可约地模糊_且_你确实观察到了赶工时，才去**隐藏后面的步骤**——而隐藏只有跨越一个真正的上下文边界才管用（一次用户触发的交接或一次子 agent 派发；一次内联的模型触发调用会把后面的步骤留在上下文里，什么也清不掉）。它是底层功夫变薄的一个成因，但与之不同：即便一个步骤跑到完全完成，底层功夫也可能是薄的。

_避免_：过早收尾、赶工、匆忙、抄近路

### 否定式 (Negation)

_失败模式。_ 靠禁止来引导——告诉 agent 不_要_做什么——这会把被禁的行为拽进上下文，使它_更_可用，而非更不可用。_别去想一头大象_，于是满脑子只剩大象；_绝不要写啰嗦的注释_，于是啰嗦正是 agent 刚读到的那个模式。禁令是一个弱修饰语，被强烈激活的那个概念淹没，于是这条禁令有一半被读成了去做那件事的指令。它的**引导词**就是那头_大象_：任何禁令招进画面里的东西。解药：提示**正面**行为——描述目标行为（“写单行注释”），这样被禁的那个就从不被说出口。禁令只有在你无法正面表述的行为上作为一道硬护栏时才有一席之地；即便如此，也要把它与正面目标配对，好让注意力落在该做的事情上。

_避免_：反讽反弹、别去想式提示、粉红大象

## 修剪 (Pruning)

让技能保持精简——每种疗法都与它所治愈的失败配对。

### 单一事实来源 (Single Source of Truth)

一种理想状态：每个含义都住在唯一一处权威的地方，因此对技能行为的一次改动就是一处的改动。**重复**是对它的违反。

_避免_：归处、规范位置

### 重复 (Duplication)

_失败模式。_ 同一个含义被给了不止一个**单一事实来源**。它花掉维护（改一处，你就得改其余各处）、花掉 token，并且抬高显著性——重复一个含义会让它在阶梯上的分量超过它真实的排位。它是**引导词**的意外反面，后者靠重复一个 token（而非含义）来有意提高注意力。

_避免_：重述、冗余

### 相关性 (Relevance)

一行是否仍然关乎技能所做之事——判断该保留什么的透镜。一行失去相关性，要么是因为它从不关乎任务（纯粹的铺陈，或一个本应被披露的**分支**），要么是因为它变陈旧：随着它所描述的行为或世界的变化而过时。更短的技能更容易保持相关，因为每一行的检查成本更低。它与**空操作**不同：相关性问的是一行是否关乎任务，而不是它是否改变行为。

_避免_：承重、陈旧、新鲜

### 沉积 (Sediment)

_失败模式。_ 一层层沉淀在技能里、从未被清理的旧内容，因为添加让人感觉安全而移除让人感觉冒险——于是陈旧、无关的行不断堆积，你必须往下钻穿它们才能找到仍然活着的东西。它是任何缺乏修剪纪律的技能的默认归宿；是**相关性**的缓慢侵蚀，与**重复**的“含义被重复”相对。

_避免_：累积、臃肿、垃圾、腐烂

### 空操作 (No-Op)

_失败模式。_ 一条什么都不改变的指令，因为模型默认就会那样做——你付出负载去告诉 agent 它本来无论如何都会做的事。判准：一行相对默认是否改变行为？一行可以完全**相关**却仍是空操作。让**引导词**免费的那些先验，同样让空操作一文不值。

引导词是一种_技法_；空操作是对一行的一个_裁决_——二者交叉。一个弱到无法胜过默认的引导词就是空操作（_be thorough_，而 agent 本就相当彻底），修法是换一个能通过裁决的更强的词（_relentless_），而不是换一种技法。所以空操作判准——它相对默认是否改变行为？——同时也是你评判一个引导词是否配得上它那些重复的方式。这是相对于模型的，而非相对于读者：两个人为某行是否空操作争执，其实是在为“默认是什么”争执，而这要靠运行技能来定夺，而不是靠辩论。

_避免_：冗余指令、重申显而易见之事、絮叨
