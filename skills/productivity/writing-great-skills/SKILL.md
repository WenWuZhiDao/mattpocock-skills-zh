技能的存在是为了从一个随机系统中攫取确定性。**可预测性（Predictability）** —— 智能体在每次运行时采取相同的_过程_，而非产出相同的输出 —— 是根本美德；下文的每个杠杆都服务于它。

**加粗术语**在 [`GLOSSARY.md`](GLOSSARY.md) 中有定义；到那里查找它们的完整含义。

## Invocation

两个选择，权衡不同的成本：

- 一个 **model-invoked** 技能保留一个 **description**，因此智能体能自主触发它，_并且_其他技能也能触达它（你仍然也可以输入它的名字）。它会贡献**上下文负荷（context load）** —— description 每一轮都待在窗口里。做法：省略 `disable-model-invocation`，并写一个面向模型、带丰富触发措辞的 description（"当用户想要……、提到……时使用"）。
- 一个 **user-invoked** 技能把 description 从智能体的可达范围中剥离：只有你，输入它的名字，才能调用它 —— 别的技能都不能。零上下文负荷，但它花掉**认知负荷（cognitive load）**：_你_就是那个必须记住它存在的索引。做法：设置 `disable-model-invocation: true`；`description` 变为面向人类 —— 一行摘要，剥去触发列表。

只有当智能体必须自行触达该技能、或另一个技能必须触达它时，才选择模型调用。如果它只会手动触发，就把它做成用户调用，不付任何上下文负荷。

当用户调用技能激增到超出你所能记住的程度时，那堆积起来的认知负荷可用一个**路由器技能（router skill）**来治愈：一个用户调用技能，命名其他技能以及何时取用每一个。

## 编写 description

一个模型调用的 **description** 做两件事 —— 陈述这个技能是什么，并列出应当触发它的**分支（branches）**。每一个词都增加**上下文负荷（context load）**，所以 description 比正文值得更狠的修剪：

- **把技能的引导词前置** —— description 正是它发挥调用作用的地方。
- **每个分支一个触发。** 给单个分支改名的同义词是**重复（duplication）** —— "用 TDD 构建功能……请求测试先行的开发"是把一个分支写了两遍。把它们合并；只保留真正不同的分支。
- **删掉正文里已有的身份陈述。** description 只保留触发，外加任何"当另一个技能需要……"的可达条款。

## 信息层级

一个技能由两种内容类型构建 —— **步骤（steps）**与**参考（reference）** —— 它们自由混合：一个技能可以全是步骤、全是参考，或二者兼有。核心决策是用哪一种、以及每一种在**信息层级（information hierarchy）**上处于何处 —— 这架阶梯按智能体需要该材料的迫切程度排序：

1. **In-skill step** —— `SKILL.md` 中的一个有序动作，主要层级：智能体按顺序做什么。每一步都终结于一个**完成判据（completion criterion）**，即告诉智能体工作已完成的条件。让它_可核查_（智能体能否分辨完成与未完成？），并在重要处让它_穷尽_（"每一个被修改的模型都有交代"，而非"产出一份变更清单"）—— 一个含糊的判据会招致**过早完成（premature completion）**。
2. **In-skill reference** —— `SKILL.md` 中的一个定义、规则或事实，按需查阅。常常是一个名正言顺的扁平对等集（一次评审的每条规则都在同一梯级上）—— 一种良好的排布，而非坏味道。_本技能全是参考。_
3. **External reference** —— 从 `SKILL.md` 中推出到一个独立文件的参考，通过一个**上下文指针（context pointer）**触达，只有当指针触发时才加载。（涵盖_已披露的_参考 —— 像 `GLOSSARY.md` 这样的兄弟文件，仍是技能的一部分 —— 直到完全**外部的参考（external reference）**，后者存在于技能系统之外、任何技能都可以指向它。）

一个要求苛刻的完成判据驱动细致的**繁重工作（legwork）** —— 即智能体在工作内部所做的挖掘 —— 无论技能是否有步骤，因为"每条规则都已应用"约束扁平参考，正如"每一步都已完成"约束一段序列。

往下推得太少，顶端就臃肿；往下推得太多，你就藏起了智能体实际需要的材料。这一张力就是整个决策。

**渐进式披露（Progressive disclosure）**就是沿阶梯往下的动作 —— 从 `SKILL.md` 移出到一个被链接的文件 —— 好让顶端保持易读。做法：技能文件夹中的一个被链接的 `.md` 文件，以它所存放的内容命名（本技能把它的完整定义披露到 `GLOSSARY.md`）。有些技能会以不止一种方式被使用，而每一种独特的方式都是一个**分支（branch）** —— 不同的运行走过技能的不同路径。分支是最干净的披露检验：内联每个分支都需要的东西，把只有部分分支才触达的东西推到指针之后。一个**上下文指针（context pointer）**的_措辞_，而非它的目标，决定智能体何时以及多可靠地触达该材料。

阶梯决定一部分处于_多低_的位置，而**共置（co-location）**决定它到了那里之后_什么东西挨着它_：把一个概念的定义、规则和注意事项归在同一个标题之下而非散落各处，这样读到其中一部分就会把它的邻居一并带来。

## 何时拆分

**粒度（Granularity）**是你把技能划分得多细，而每一种切法都会花掉两种负荷之一，所以只在这一切法值得时才拆分。两种切法：

- **按调用** —— 当你有一个独特的**引导词（leading word）**应当自行触发它，或另一个技能必须触达它时，就把一个 **model-invoked** 技能拆出来。你要为这个新的、始终加载的 **description** 付出**上下文负荷（context load）**，所以那种独立的可达性必须值得。
- **按序列** —— 当前方尚待完成的步骤（某一步的**后续步骤（post-completion steps）**）诱使智能体草草了事面前这一步（**过早完成（premature completion）**）时，就拆分一段**步骤（steps）**。把它们移出视野会鼓励智能体在当前任务上做更多**繁重工作（legwork）**。

## Pruning

把每个含义保持在一个**单一事实来源（single source of truth）**里：一个权威之处，这样改变行为就是一处的编辑。

逐行核查**相关性（relevance）**：它是否仍与技能所做之事有关？

然后逐句而非仅逐行地猎捕**空操作（no-ops）**：对每个句子单独运行空操作检验，当某一句未通过时，删掉整句而非从中删词。要激进 —— 大多数未通过的散文该删除，而非重写。

## 引导词

一个**引导词（leading word）**是一个已经存在于模型预训练中的紧凑概念，智能体在运行技能时会借它来思考（例如 _lesson_、_fog of war_、_tracer bullets_）。在全文中反复使用（不过未必如此 —— 一个强有力的引导词可能只需要一次），它积累出一个分布式定义，并通过招募模型已持有的先验，用尽可能少的 token 锚定一整片行为区域。

它服务于可预测性两次。在正文中它锚定_执行_：每次该词出现时，智能体都会取用相同的行为。在 description 中它锚定_调用_：当同一个词存在于你的提示、文档和代码中时，智能体会把这种共享语言与该技能关联起来，从而更可靠地触发它。

去寻找机会，把技能重构为使用引导词。一个在三处铺陈开来的三元组（**重复**）、一个花掉一整句去比划一个想法的 description —— 每一个都是一段乞求**坍缩**成单个 token 的文字。示例包括：

- "fast、deterministic、low-overhead" -> _tight_ —— 一个跨阶段被反复陈述的品质 —— 坍缩成单个预训练词（一个 _tight_ 回路）。
- "a loop you believe in" -> _red_ —— 把一个模糊的门槛转化为一个二元可观测状态（回路在 bug 上变_红_，或者没有）。

你赢了两次：更少的 token，_并且_给智能体一个更锐利的挂钩来悬挂它的思考。假定每个技能都携带着可被引导词淘汰的重复陈述 —— 去把它们找出来。

## 失效模式

用这些来诊断用户在使用该技能时可能遇到的问题。

- **Premature completion** —— 在一步真正完成之前就结束它，注意力滑向了_"完成"本身_。防御，按顺序：先打磨完成判据（廉价、局部）；只有当它不可化约地模糊_并且_你观察到那种匆忙时，才通过拆分（序列切法）来隐藏后续步骤。
- **Duplication** —— 同一个含义存在于不止一处。耗费维护与 token，并把一个含义在阶梯上的显著性抬到超出其真实排位。
- **Sediment** —— 因添加感觉安全、移除感觉有风险而沉淀下来的陈旧层次。任何缺乏修剪纪律的技能的默认命运。
- **Sprawl** —— 一个技能单纯就是太长，即便每一行都有效且独一无二。损害可读性与可维护性并浪费 token。解药是那架阶梯：把**参考（reference）**披露到指针之后，并按**分支（branch）**或序列拆分，使每条路径只承载自己所需。
- **No-op** —— 一行模型默认就会遵守的指令，于是你付出负荷却什么也没说。检验：它相较于默认是否改变行为？一个弱引导词（当智能体本已相当细致时还说 _be thorough_）是空操作；修法是换一个更强的词（_relentless_），而非换一种技术。
